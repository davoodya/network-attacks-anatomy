#### 4: Yersinia - a Framework for Layer 2 Attacks
##### Basic & Concepts
در ادامه مباحث ماژول ابزارهای حمله مرد میانی (MITM Tools)، در این بخش به بررسی کامل یکی از تخصصی‌ترین و قدرتمندترین فریم‌ورک‌های تحلیل و تست امنیت پروتکل‌های لایه دوم شبکه، یعنی Yersinia می‌پردازیم. تمامی مباحث مطرح شده در این قسمت صرفاً جنبه آموزشی و پژوهشی داشته و برای استفاده در محیط‌های آزمایشگاهی و ایزوله طراحی شده است. هرگونه استفاده نادرست و خارج از چارچوب آموزش، بر عهده استفاده‌کننده می‌باشد.
###### Introduction to Yersinia
**معرفی و توصیف Yersinia:**
ابزار Yersinia یک فریم‌ورک تخصصی و متن‌باز (Open Source) است که برای تحلیل امنیتی، تست نفوذ و ارزیابی پایداری پروتکل‌های لایه دوم شبکه (Data Link Layer) طراحی شده است. این ابزار توسط اسلاویک و رامون طراحی و با زبان برنامه‌نویسی C نوشته شده است و به متخصصان امنیت تهاجمی (Red Team) و تیم‌های دفاعی (Blue Team) این امکان را می‌دهد تا آسیب‌پذیری‌های موجود در پیاده‌سازی پروتکل‌های حیاتی نظیر STP(Spanning Tree Protocol) و DHCP را پیش از آنکه مورد سواستفاده عوامل مخرب قرار گیرد، شناسایی و برطرف کنند. نام این ابزار از باکتری یرسینیا پستیس (Yersinia pestis) که عامل بیماری طاعون است، الهام گرفته شده که کنایه‌ای از قدرت تخریب‌کنندگی آن در صورت عدم وجود تنظیمات امنیتی صحیح در شبکه دارد.

هدف اصلی از توسعه Yersinia، پر کردن خلأ دانشی و ابزاری در حوزه تست نفوذ لایه دوم بود؛ زیرا بیشتر ابزارهای موجود مانند Ettercap و Dsniff تنها بر روی حملات ARP Spoofing تمرکز داشتند، در حالی که Yersinia پروتکل‌های مدیریتی و کنترلی زیرساخت شبکه را هدف قرار می‌دهد

- **ویژگی‌های کلیدی:**
- **معماری ماژولار:** هر پروتکل به صورت یک ماژول مجزا پیاده‌سازی شده و قابلیت افزودن پروتکل‌های جدید وجود دارد.
- **چندین حالت اجرایی:** ابزار دارای 4 حالت اجرایی متفاوت است:
    1. **حالت گرافیکی (GUI - GTK):** مناسب برای محیط‌های دسکتاپ.
    2. **حالت متنی تعاملی (ncurses):** برای کار در ترمینال بدون نیاز به محیط گرافیکی.
    3. **حالت خط فرمان (Command Line):** مناسب برای اسکریپت‌نویسی و اتوماسیون.
    4. **حالت سرویس شبکه (Daemon):** امکان کنترل از راه دور از طریق پروتکل Telnet بر روی پورت 12000.
- **پشتیبانی از پروتکل های خاص:**
	- یکی از ویژگی های برتر Yersinia پشتیبانی از پروتکل هایی است که کمتر مورد توجه هستند. پروتکل‌هایی از قبیل:
		- STP, RSTP, CDP, DTP, VTP, HSRP, ISL, 802.1Q, 802.1X, DHCP و MPLS
		- STP (Spanning Tree Protocol)
		- RSTP (Rapid Spanning Tree Protocol)
		- CDP (Cisco Discovery Protocol)
		- DTP (Dynamic Trunking Protocol)
		- VTP (VLAN Trunking Protocol)
		- HSRP (Hot Standby Router Protocol)
		- ISL (Inter Switch Link - VLAN Tagging)
		- DHCP (Dynamic Host Configuration Protocol)
		- MPLS (Multi Protocol Label Switching)
		- IEEE 802.1Q (VLAN Tagging)
		- IEEE 802.1X (Port‑Based Network Access Control)

- **آدرس مخزن رسمی ابزار در گیت‌هاب:**
	- https://github.com/tomac/yersinia Original Yersinia
	- https://github.com/tomac/yersinia-web Yersinia Web Version
###### Installation Methods
برای نصب Yersinia در سیستم‌عامل‌های مبتنی بر دبیان مانند کالی لینوکس، ابتدا مخازن را به‌روزرسانی کرده و سپس ابزار را نصب می‌کنیم. همچنین برای بهره‌مندی از حداکثر قابلیت‌ها، معمولاً نصب از طریق Source Code توصیه می‌شود.

1. **روش اول: نصب از طریق مخازن رسمی (APT)**
```sh
sudo apt update
sudo apt install yersinia
```

2. **روش دوم: کامپایل از سورس (پیشنهادی برای آخرین نسخه)**  
	- پیش‌نیازهای لازم برای کامپایل شامل کتابخانه‌های `libpcap` و `libnet` می‌باشد.
```sh
#نصب پیش‌نیازها
sudo apt update
sudo apt install build-essential libpcap-dev libnet1-dev libgtk2.0-dev autoconf

#دانلود سورس
wget https://github.com/tomac/yersinia/archive/refs/tags/v0.8.2.tar.gz
tar -xzf v0.8.2.tar.gz
cd yersinia-0.8.2

#کامپایل و نصب
./autogen.sh
./configure
make
sudo make install
```
نکته: اگر تمایل به استفاده از رابط گرافیکی (GUI) نداریم، می‌توانیم هنگام اجرای `configure` از گزینه `disable-gtk--` استفاده کنیم.

3. **روش سوم(در صورت بروز مشکل):**
	- اگر برای نصب از سورس کد و کامپایل به مشکل برخوردید، پیش نیازهای زیر را نیز نصب کنید و سپس کامپایل را به روش زیر انجام دهید.(در بعضی از توزیع ها ممکن است روش اصلی انجام نشود، اما در اکثر سیستم ها روش اصلی بدون مشکل انجام میشود)
```sh
sudo apt install -y gettext autopoint libtool
sudo apt install -y libnet1 libnet1-dev
sudo apt install -y libgtk2.0-dev pkg-config build-essential git autoconf automake

git clone https://github.com/amierattia/yersinia.git
cd yersinia

autoupdate
autoreconf -i
./configure
make
sudo make install

cd src
sudo ./yersinia -G
```
##### Flags & Parameters
ابزار Yersinia از فلگ‌های متعددی برای کنترل نحوه اجرا پشتیبانی می‌کند. تسلط بر این پارامترها برای استفاده حرفه‌ای از ابزار ضروری است.

| فلگ                 | توضیحات                                            |
| ------------------- | -------------------------------------------------- |
| `-h` یا `--help`    | نمایش راهنمای ابزار.                               |
| `-V` یا `--Version` | نمایش نسخه فعلی نصب شده.                           |
| `-G`                | اجرای ابزار در حالت گرافیکی (GTK).                 |
| `-I`                | اجرای ابزار در حالت تعاملی ترمینال (ncurses).      |
| `-D`                | اجرای ابزار در حالت سرویس (Daemon) روی پورت 12000. |
| `-d`                | فعال‌سازی حالت دیباگ برای مشاهده جزئیات بیشتر.     |
| `-i [Interface]`    | مشخص کردن اینترفیس شبکه (مثلاً `eth0`).            |
| `-attack [Number]`  | اجرای مستقیم یک حمله با شماره مشخص.                |
| `-c [File]`         | بارگذاری فایل تنظیمات Configuration.               |
| `-l [File]`         | ذخیره خروجی در فایل لاگ.                           |
| `-M`                | غیرفعال‌سازی قابلیت جعل مک آدرس (MAC Spoofing).    |

##### Attack Types Implemented using Yersinia
در این بخش، به تشریح کامل و جامع حملات پروتکل‌های مختلف با استفاده از فریم‌ورک Yersinia می‌پردازیم. هر حمله با یک شناسه عددی (Attack ID) مشخص می‌شود که برای اجرا از طریق خط فرمان به کار می‌رود. 
همانطور که پیش‌تر تأکید شد، تمامی دستورات و سناریوهای ارائه‌شده صرفاً برای یادگیری مفاهیم امنیت شبکه در محیط‌های آزمایشگاهی و ایزوله طراحی شده‌اند. هرگونه به‌کارگیری این تکنیک‌ها در شبکه‌های واقعی بدون مجوز کتبی از مالک آن، غیرقانونی بوده و مسئولیت آن کاملاً بر عهده استفاده‌کننده است.
###### 1: DHCP (Dynamic Host Configuration Protocol) Attacks
پروتکل DHCP برای تخصیص خودکار تنظیمات IP به کار می‌رود. این پروتکل از آن جهت در مقوله حملات مرد میانی اهمیت دارد که با ایجاد تداخل در سرور اصلی و راه‌اندازی سرور جعلی، می‌توانیم دروازه (Default Gateway) ترافیک هدف را به سمت خود تغییر دهیم. با اینکار تمام ترافیک سیستم هدف به سمت ما روانه میشود.

- در Yersinia حملات DHCP را در چندین مدل متفاوت میتوانیم پیاده سازی کنیم، برای انتخاب نوع حمله باید از عدد مربوط به آن استفاده کنیم که در ادامه این اعداد را معرفی میکنیم.
0. **`-attack 0` Send DHCP Packet:**
	- در مدل 0 از حملات DHCP بسته خام DHCP برای تست صحت عملکرد سرور ارسال میشود.
```sh
sudo yersinia dhcp -attack 0 -i eth0
```

1. **`-attack 1` DHCP Starvation (DoS):**
	- حمله DHCP Starvation (خستگی IP Pool) نوعی حمله DoS
	- **تئوری:** مهاجم با جعل مک‌آدرس‌های متفاوت، تعداد زیادی درخواست `DHCPDISCOVER` ارسال می‌کند تا تمامی آدرس‌های موجود در استخر (Pool) سرور DHCP را اشغال کند.
	- **کاربرد:** ایجاد اختلال در سرویس‌دهی به کاربران جدید (Denial of Service) و به‌عنوان پیش‌نیاز حمله DHCP Spoofing.
	- **مکانیزم:** ارسال سیل‌آسای بسته‌های UDP از پورت 68 به پورت 67.
	- **سناریو آموزشی:** فرض کنیم می‌خواهیم یک سرور DHCP جعلی را جایگزین سرور اصلی کنیم. ابتدا باید IP Pool سرور اصلی را خالی کنیم تا اهداف مجبور به پذیرش IP از سرور جعلی ما شوند.
```sh
sudo yersinia dhcp -attack 1 -i eth0
```

2. **`-attack 2` Rogue DHCP Server:**
	1. راه‌اندازی سرور DHCP جعلی (Rogue DHCP Server)
	2. **تئوری:** پس از غیرفعال‌سازی سرور اصلی (یا رقابت با آن)، یک سرور DHCP جعلی در شبکه ایجاد می‌شود که آدرس Default Gateway را به آدرس دستگاه ما تنظیم می‌کند.
	3. **کاربرد:** اجرای حمله مرد میانی (MITM) از طریق رهگیری ترافیک خروجی اهداف.
	4. **پیاده‌سازی:** این حمله معمولاً نیازمند تنظیمات دستی در فایل کانفیگ برای مشخص کردن Gateway جعلی است.
```sh
sudo yersinia dhcp -attack 2 -i eth0
```

3. **`-attack 3` DHCP Release (DoS):**
	- حمله رهاسازی آیپی DHCP Release برای قطع اجباری اتصال شبکه
	- **تئوری:** ارسال بسته‌های DHCPRELEASE با MAC Address اهداف. این کار باعث می‌شود سرور DHCP تصور کند که هدف دیگر نیازی به IP ندارد و IP را آزاد کند.
	- **کاربرد:** قطع اجباری اتصال شبکه یک میزبان خاص.
```sh
sudo yersinia dhcp -attack 3 -i eth0
```

###### 2: STP (Spanning Tree Protocol) Attacks
پروتکل STP برای جلوگیری از Loop لایه 2 در توپولوژی‌های دارای افزونگی استفاده می‌شود. با دستکاری آن می‌توانیم توپولوژی شبکه را تغییر دهیم تا ترافیک از دستگاه ما عبور کند.

0. **`-attack 0` Send BPDU Config:**
	- ارسال بسته پیکربندی BPDU Config دست ساز (Attack 0)
	- **تئوری:** ارسال یک بسته BPDU پیکربندی دست‌ساز برای تست رفتار سوئیچ.
	- **کاربرد:** تحلیل واکنش سوئیچ به تغییرات توپولوژی.
	- **مکانیزم:** تزریق یک بسته با فیلدهای مشخص.
	- **پیاده‌سازی:**
```sh
sudo yersinia stp -attack 0 -i eth0
```

1. **`-attack 1` TCN BPDU for Changing Topology:**
	- ارسال TCN BPDU برای تغییر توپولوژی (Attack 1)
	- **تئوری:** ارسال بسته TCN (Topology Change Notification) که باعث می‌شود سوئیچ‌ها جدول MAC Address خود را سریع‌تر پاکسازی (Flush) کنند.
    - **کاربرد:** افزایش بار پردازشی سوئیچ‌ها و شنود ترافیک بیشتر، زیرا سوئیچ فریم‌ها را برای همه پورت‌ها ارسال می‌کند.
    - **مکانیزم:** تزریق دوره‌ای بسته‌های TCN.
    - **پیاده‌سازی:**
```sh
sudo yersinia stp -attack 1 -i eth0
```

2. **`-attack 2` Config BPDU Flood Attack (DoS):**
	1. حمله ارسال سیل آسا پیام BPDU Config برای از کارانداختن پردازش در شبکه (Attack 2) (DoS)
	- **تئوری:** ارسال حجم عظیمی از بسته‌های Config BPDU برای اشغال پردازنده سوئیچ و ایجاد اختلال در محاسبات STP.
	- **کاربرد:** ایجاد اختلال در شبکه و ناپایدارسازی توپولوژی.
	- **مکانیزم:** ارسال سیل‌آسای بسته‌ها با نرخ بالا.
	- **پیاده‌سازی:**
```sh
sudo yersinia stp -attack 2 -i eth0
```

3. **`-attack 3` TCN BPDU Flood Attack (DoS):**
	- حمله ارسال سیل آسا پیام TCN BPDU بمنظور ایجاد اختلال در شبکه (Attack 3) (DoS)
	- **تئوری:** ارسال سیل‌آسای بسته‌های TCN که سوئیچ را وادار می‌کند بی‌وقفه جدول مک خود را پاکسازی کند.
	- **کاربرد:** حملات DoS شدید که منجر به Broadcast شدن بیش از حد ترافیک می‌شود.
	- **مکانیزم:** ارسال مستمر بسته‌های TCN جعلی.
	- **پیاده‌سازی:**
```sh
sudo yersinia stp -attack 3 -i eth0
```

4. **`-attack 4` Claiming Root Role:**
	- حمله تصاحب نقش Root ریشه (Attack 4)
	- **تئوری:** سوئیچ‌های شبکه با تبادل بسته‌های BPDU یکدیگر را کشف کرده و یک سوئیچ به عنوان ریشه (Root Bridge) انتخاب می‌شود. ما با ارسال BPDU با اولویت (Priority) پایین‌تر (مقدار عددی کمتر) خود را به عنوان Root معرفی می‌کنیم.
	- **کاربرد:** تبدیل شدن به نقطه مرکزی ترافیک (Root Bridge). هنگامی که Root شویم، ترافیک عبوری از سوئیچ‌ها از ما عبور خواهد کرد.
	- **مکانیزم:** جعل Bridge ID با Priority 0.
	- **پیاده‌سازی:**
```sh
sudo yersinia stp -attack 4 -i eth0
```

5. **`-attack 5` Claiming Other Role:**
	- حمله تصاحب سایر نقش ها (Attack 5)
	- **تئوری:** معرفی خود به‌عنوان یک سوئیچ مجازی با اولویت محاسبه‌شده برای قرار گرفتن در موقعیت‌های خاص Spanning Tree
	- **کاربرد:** تغییر مسیر ترافیک بین دو شاخه خاص از شبکه.
	- **پیاده‌سازی:**
```sh
sudo yersinia stp -attack 5 -i eth0
```

6. **`-attack 6` Claiming Root Role with MiTM:**
	- حمله Claiming Root Role با دو رابط (Attack 6 - MITM)
    - **تئوری:** این نوع حمله مخصوص ایجاد موقعیت مرد میانی است. اگر دو کارت شبکه ما به دو شبکه مختلف متصل باشد، با اجرای این حمله، خود را به‌عنوان مسیر بین دو سوئیچ معرفی می‌کنیم.
    - **کاربرد:** حمله مرد میانی کامل (MITM).
    - **مکانیزم:** جعل BPDU و تزریق Bridge ID جدید.
    - **سناریو:** اتصال کابل‌های شبکه از دو کارت شبکه به دو سوئیچ اکسس (Access Switch Port) مختلف.
    - **پیاده‌سازی:**
```sh
- sudo yersinia stp -attack 6 -i eth0
```

###### 3: CDP (Cisco Discovery Protocol) Attacks
0. **`-attack 0` CDP Packet Sending:**
	- ارسال بسته CDP خام (Attack 0)
	- **تئوری / کاربرد:** ارسال یک بسته دستی برای تست حضور و شناسایی اطلاعات.
```sh
sudo yersinia cdp -attack 0 -i eth0
```

1. **`-attack 1` CDP Flooding Attack(CDP Table Flooding) (DoS):**
	- حمله Flooding به جدول CDP نوعی از DoS (Attack 1)
	- **تئوری:** سوئیچ‌های سیسکو اطلاعات همسایگان خود را در جدولی با حافظه محدود ذخیره می‌کنند. با ارسال سیل‌آسای (Flooding) بسته‌های CDP جعلی حاوی شناسه‌های تصادفی، این جدول پر شده و ممکن است باعث Crash یا عملکرد ناپایدار سوئیچ شود.
    - **پیاده‌سازی:**
```sh
sudo yersinia cdp -attack 1 -i eth0
```

2. **`-attack 2` Setting up a Virtual Device:**
	- راه اندازی دستگاه مجازی
	- **تئوری:** شبیه‌سازی یک دستگاه سیسکو در شبکه که می‌تواند اطلاعات گمراه‌کننده به سوئیچ اصلی بدهد.
	- **کاربرد:** مخفی‌سازی و تغییر دید مدیر شبکه نسبت به توپولوژی.
	- **پیاده‌سازی:**
```sh
sudo yersinia cdp -attack 2 -i eth0
```
###### 4: DTP (Dynamic Trunking Protocol) Attacks.
0. **`-attack 0` DTP Packet Sending:**
	- ارسال بسته DTP خام (Attack 0)
	- **تئوری / کاربرد:** تست و عیب‌یابی فرآیند مذاکره ترانک.
	- **پیاده سازی:**
```sh
sudo yersinia dtp -attack 0 -i eth0
```

1. **`-attack 1` Enabling Trunk:**
	- حمله فعال‌سازی ترانک (Attack 1)
	- **تئوری:** DTP پروتکلی برای مذاکره خودکار پورت‌ها جهت تبدیل شدن به Trunk است. اگر پورت سوئیچ به صورت Dynamic Auto یا Dynamic Desirable تنظیم شده باشد، می‌توانیم با ارسال بسته‌های DTP، پورت را به Trunk تبدیل کنیم.
	- **کاربرد:** دستیابی به ترافیک تمام VLAN های عبوری از آن پورت (VLAN Hopping)
	- **پیاده سازی:**
```sh
sudo yersinia dtp -attack 1 -i eth0
```

###### 5: 802.1Q (VLAN Hopping) Attacks
0. **`-attack 0` 802.1Q Packet Sending:**
	- ارسال بسته 802.1Q خام (Attack 0)
	- **تئوری / کاربرد:** تزریق یک فریم tagged دستی برای تحلیل رفتار سوئیچ.
	- **پیاده سازی:**
```sh
sudo yersinia 802.1q -attack 0 -i eth0
```

1. **`-attack 1` Double Encapsulation:**
	- **تئوری:** ارسال فریمی که دارای دو تگ 802.1Q است. تگ اول متعلق به VLAN مقصد ما و تگ دوم متعلق به VLAN مبدأ است. اگر سخت‌افزار سوئیچ به درستی پیاده‌سازی نشده باشد، تگ اول را جدا کرده و فریم را وارد VLAN دوم می‌کند.
	- **کاربرد:** ارسال ترافیک به VLANهایی که به آن‌ها دسترسی نداریم.
	- **پیاده سازی:**
```sh
sudo yersinia 802.1q -attack 1 -i eth0
```

2. **`-attack 2` ARP Poisoning on VLAN (DoS):**
	- اجرای ARP Poisoning در بستر VLAN (DoS) - (Attack 2)
	- **تئوری:** تزریق بسته‌های ARP جعلی برای اختلال در ارتباط دروازه و کلاینت‌ها.
	- **مکانیزم / روش اجرا:** در ابتدا با ارسال DTP حمله 1 ترانک را فعال میکنیم، سپس با 802.1Q حمله 2 و وارد کردن IP هدف، IP Gateway و یک IP آزاد، عملیات MITM را اجرا می‌کنیم.
	- **کاربرد:** ایجاد DoS یا شنود ترافیک بین دو VLAN
	- **پیاده سازی:**
```sh
sudo yersinia 802.1q -attack 2 -i eth0
```
###### 6: HSRP (Hot Standby Router Protocol)
پروتکل HSRP برای افزایش دسترسی‌پذیری (High Availability) دروازه‌های شبکه Network Gateways استفاده می‌شود. این حمله یکی از کلاسیک‌ترین و مؤثرترین حملات MITM است.
0. **`-attack 0` HSRP Packet Sending:**
	- ارسال بسته HSRP خام (Attack 0)
	- **تئوری / کاربرد:** تست ساختار و احراز هویت پروتکل HSRP.
	- **پیاده سازی:**
```sh
sudo yersinia hsrp -attack 0 -i eth0
```

1. **`-attack 2` Becoming Active Router (MITM):**
	- حمله تبدیل شدن به روتر فعال (Attack 2 - MITM)
	- **تئوری:** در گروه HSRP، یک روتر فعال (Active) و یک روتر آماده به کار (Standby) وجود دارد. روتر فعال ترافیک را پاسخ می‌دهد. ما با ارسال بسته‌های HSRP با Priority بالاتر (مثلاً 255) و جعل MAC Address مجازی، خود را به عنوان روتر Active معرفی می‌کنیم.
	- **کاربرد:** رهگیری کل ترافیک خروجی از شبکه به سمت اینترنت، چراکه Default Gateway کاربران همان IP مجازی HSRP است.
	- **مکانیزم:** جعل MAC Address مجازی.
	- **سناریو:** روتر فعلی دارای Priority 100 است. ما دستور زیر را اجرا می‌کنیم تا با اولویت 255 جایگزین آن شویم.
```sh
sudo yersinia hsrp -attack 2 -i eth0
```

##### Yersinia Configuration
ابزار Yersinia از یک فایل کانفیگ مرکزی (معمولاً `yersinia.conf`) برای شخصی‌سازی عمیق حملات استفاده می‌کند. این فایل به ما اجازه می‌دهد مقادیر فیلدهای پروتکل‌ها را پیش از ارسال، مطابق با نیاز سناریوی آموزشی خود تغییر دهیم.

###### `yersinia.conf` Main Configuration 
محل فایل کانفیگ: معمولاً در مسیر `/etc/yersinia/yersinia.conf` قرار دارد، همچنین میتوانیم در دایرکتوری جاری یک فایل جدید با پسوند `conf.` ایجاد کنیم و سپس با فلگ `c-` در ابزار فایل را فراخوانی کنیم. در این فایل یک بخش Global برای تنظیمات عمومی وجود دارد و همچنین برای هر پروتکل نیز بخش های مجزایی وجود دارد.


- **بخش‌های کلیدی فایل کانفیگ:**
	- فایل از تگ‌های XML-like برای تفکیک پروتکل‌ها استفاده می‌کند.

1. **بخش عمومی (Global): تنظیمات کلی ابزار.**
	1. `mac_spoofing`: فعال/غیرفعال کردن جعل مک (مقدار 1 یا 0).
	2. `interfaces`: تعیین اینترفیس‌های فعال.
	3. `username/password`: تعیین نام کاربری و رمز عبور برای حالت Daemon.

2. **بخش پروتکل DHCP:**
```sh
<protocol DHCP>
Source MAC = 02:48:33:66:02:51 #مک آدرس مبدا
Destination MAC = FF:FF:FF:FF:FF:FF  #مک آدرس مقصد (Broadcast)
SIP = 000.000.000.000   #آیپی مبدا (معمولاً 0.0.0.0 برای سرور جعلی)
DIP = 255.255.255.255   #آیپی مقصد (Broadcast)
SPort = 00068           #پورت مبدا - DHCP Client
DPort = 00067           #پورت مقصد - DHCP Server
Xid = 0x643C9869        #شناسه تراکنش
Flags = 0x8000          #Broadcast Flag
SI = 192.168.1.100      #آیپی DHCP Server (در حمله جعلی این آیپی خودمان است)
```
برای اجرای یک حمله Rogue DHCP Server، باید پارامتر `SI` (Server IP) را در این فایل ویرایش کنیم و بر روی آیپی خودمان یا سیستمی قرار دهیم که میخواهیم ترافیک سیستم هدف به سمت آن هدایت شود. در واقع ترافیک برداشت شده در حمله Rogue DHCP Server به آیپی  `SI` (Server IP) هدایت Redirect میشود.

3. **بخش پروتکل STP:**
```sh
<protocol STP>
Source MAC = 0A:23:16:02:FF:08 #مک آدرس مبدا
RootId = 5080.760F0E14AC58     #شناسه Root Bridge جعلی
BridgeId = CB09.E7CD90117CAA   #شناسه Bridge ما
Priority = 0000                #با کاهش این عدد، شانس ریشه شدن افزایش می‌یابد
Hello = 0002
Max = 0014
```

4. **بخش پروتکل HSRP:**
```sh
<protocol HSRP>
Group = 00                  #شناسه گروه
Priority = 255              #هرچه بیشتر، شانس فعال شدن بالاتر
Auth = cisco                #رمز عبور پروتکل (اگر تنظیم شده باشد)
VIP = 192.168.1.1           #آی‌پی مجازی که باید جعل شود
```

- **نحوه استفاده از فایل کانفیگ:**  
	- برای اجرای یک حمله با تنظیمات شخصی‌سازی شده، ابتدا مقادیر را در فایل `myconfig.conf` ویرایش کرده و سپس ابزار را با فلگ `c-` فراخوانی می‌کنیم:
```sh
sudo yersinia -c myconfig.conf hsrp -attack 2 -i eth0
```
با این روش می‌توانیم سناریوهای پیچیده‌ای مانند جعل شناسه‌های خاص سخت‌افزاری یا تنظیم زمان‌های دقیق پروتکل‌ها را شبیه‌سازی کنیم.

##### Analyze Yersinia Attacks in Cisco Switches
در این فصل، خروجی سوئیچ و روتر های سیسکو را در زمانی که حملات Yersinia(پروتکل STP, CDP) به آنها انجام شده است مشاهده میکنیم. با اینکار میتوانیم حملاتی که سوئیچ یا روتر سیسکو انجام میشود را شناسایی کنیم و سپس به دفع حمله و ایمن سازی شبکه خود بپردازیم. در فصل های بعدی روش دفاع کامل در مقابل این حملات را نیز بررسی میکنیم.
###### 1: Configuration BPDU Sending (DoS)
- **تئوری حمله:** در این حمله، با ارسال بی‌وقفه بسته‌های BPDU پیکربندی (Configuration BPDU) که هر کدام یک Bridge ID تصادفی را به عنوان ریشه (Root) معرفی می‌کنند، پردازنده سوئیچ هدف را وادار به محاسبه مجدد و بازبینی مداوم جدول STP خود می‌کنیم. از آنجا که هر بسته، یک ریشه جدید با اولویت برابر اما Bridge ID متفاوت معرفی می‌کند، سوئیچ وارد یک چرخه پردازشی سنگین می‌شود که می‌تواند به اختلال در سرویس (DoS) منجر شود. این حمله برای ایجاد اختلال شدید در شبکه و تست تاب‌آوری سوئیچ‌ها در برابر بسته‌های کنترلی نامعتبر در محیط آزمایشگاه استفاده می‌شود.

```sh

```
    
- **مکانیزم حمله:** ابزار Yersinia بسته‌های BPDU را با مشخصات زیر تولید و روی شبکه ارسال می‌کند:

###### 3: Claiming Root Rule Attack (NON-DoS)
- **تئوری حمله:** برخلاف حملات قبلی، این یک حمله هدفمند و غیرمخرب (Non-DoS) به منظور تصاحب موقعیت سوئیچ ریشه (Root Bridge) در توپولوژی STP است. هدف ما این است که با معرفی یک Bridge ID با اولویت (Priority) عددی پایین‌تر از ریشه فعلی، سوئیچ‌ها را متقاعد کنیم که دستگاه ما Root Bridge جدید است. این حمله، پیش‌نیاز اصلی اجرای موفق یک حمله مرد میانی (MITM) در شبکه‌های سویچ شده است. با تبدیل شدن به ریشه، می‌توان مسیر ترافیک VLAN های مختلف را به سمت دستگاه خود تغییر داد.

- **کامند پیاده‌سازی حمله:**
```sh
#NON-DOS attack Claiming Root Role
sudo yersinia stp -attack 4 -i eth0
```

    
- **مکانیزم حمله:** Yersinia برای این حمله رفتار زیرکانه‌ای دارد. ابتدا شبکه را برای کشف Bridge ID ریشه فعلی شنود (Sniff) می‌کند. سپس یک بسته Configuration BPDU با مشخصات زیر ارسال می‌کند:
	- مک مبدأ: مک آدرس مشابه Root Bridge فعلی (برای معتبرتر به نظر رسیدن).
	- مقدار Bridge ID: با استفاده از Bridge ID ریشه فعلی اما با **اولویت پایین‌تر** (مثلاً اگر اولویت ریشه `32769` است، ابزار `32768` را امتحان می‌کند).
	- مقدار Root Path Cost: مشابه مقداری که ریشه فعلی اعلام کرده است.
	- سایر موارد را در بلاک زیر مشاهده میکنید:
```sh
Source MAC: same one as the sniffed BPDU.
Destination MAC: same one as the sniffed BPDU.
Bridge ID: the sniffed one slightly modified to have a lower priority
Root ID: 8000: same as bridge id.
Hello time: same one as the sniffed BPDU.
Forward delay: same one as the sniffed BPDU.
Max age: same one as the sniffed BPDU.
Root pathcost: same one as the sniffed BPDU.
```

- **خروجی سوئیچ سیسکو:** لاگ سوئیچ به وضوح فرایند تصاحب را نشان می‌دهد:
```sh
<output from the cisco log>
01:58:48: STP: VLAN0001 heard root 32769-000e.84d4.2280 on Fa0/8
01:58:48:     supersedes 32769-000e.84d5.2280
01:58:48: STP: VLAN0001 new root is 32769, 000e.84d4.2280 on port Fa0/8, cost 19
</output>
```

###### 4: CDP Table Flooding (DoS)
- **تئوری حمله:** دستگاه‌های سیسکو اطلاعات همسایگان CDP خود را در یک جدول در حافظه نگهداری می‌کنند. این حمله با ارسال سیل‌آسای بسته‌های CDP جعلی که هر کدام مشخصات یک دستگاه سیسکو واقعی را جعل می‌کنند، حافظه دستگاه هدف را به طور کامل اشغال می‌کند. دستگاه هدف تصور می‌کند هزاران همسایه جدید دارد و سعی در ذخیره اطلاعات آن‌ها می‌کند تا جایی که حافظه تمام شده و فرایندهای حیاتی مختل یا متوقف می‌شوند.DoS trying to exhaust device) memory) از این حمله برای تست استحکام دستگاه‌های شبکه در برابر حملات مصرف حافظه و ارزیابی پایداری آن‌ها تحت فشار استفاده میشود. دقت کنید که این حمله بسیار خطرناک بوده و می‌تواند منجر به کرش (Crash) کامل دستگاه شود.

- **کامند پیاده‌سازی حمله:**
```sh
sudo yersinia cdp -attack 1 -i eth0
```

    
- **مکانیزم حمله:** ابزار Yersinia بسته‌های CDP با فیلدهای معتبر اما جعلی را با نرخ بالا تولید و به آدرس CDP Multicast یعنی `01:00:0c:cc:cc:cc` ارسال می‌کند.

- **خروجی روتر سیسکو 2503:** خروجی‌های زیر از یک روتر سیسکو 2503 است که تخریب کامل سیستم را نشان می‌دهد(ناتوانی تخصیص مموری برای ثبت رکورد جدید در CDP Table):
```sh
#شکست در تخصیص حافظه
%SYS-2-MALLOCFAIL: Memory allocation of 100 bytes failed... 
#ازدحام شدید پردازه
%SCHED-3-THRASHING: Process thrashing on watched queue 'CDP packets'... 
#مصرف بیش از حد پردازنده که منجر به قطع ارتباط می‌شود
%SYS-3-CPUHOG: Task ran for 16884 msec
... 
```

- **خروجی سوئیچ سیسکو 2950:** خروجی‌های زیر از یک سوئیچ سیسکو 2950 است که ناتوانی در تخصیص مموری برای ثبت رکورد جدید در CDP Table را نشان میدهد:
```sh
00:06:08: %SYS-2-MALLOCFAIL: Memory allocation of 224 bytes failed from 0x800118D0, alignment 0
Pool: Processor  Free: 0  Cause: Not enough free memory
Alternate Pool: I/O  Free: 32  Cause: Not enough free memory
...
```

2. **ب) میان‌برها و نحوه اجرای حمله (مثال Flooding CDP Table Attack):**  
برای آشنایی عملی، یک حمله Flooding CDP Table را با هم اجرا می‌کنیم. این حمله با پر کردن حافظه سوئیچ، باعث اختلال در سرویس می‌شود که پیش‌تر در بخش Attack Types Implemented using Yersinia و CDP Attacks به تفصیل توضیح داده شده است.

- **1: اجرا:** `sudo yersinia -G` را در ترمینال اجرا می‌کنیم.
    
- **2: انتخاب اینترفیس:** از منوی `File` گزینه `Select Interface` را انتخاب کرده و اینترفیس متصل به شبکه هدف (مثلاً `eth0`) را مشخص می‌کنیم.
    
- **3: انتخاب پروتکل:** در پنل سمت چپ، بر روی `CDP` کلیک می‌کنیم تا لیست حملات آن در پنل میانی بارگذاری شود.
    
- **4: انتخاب حمله:** در پنل میانی، روی `[1] (DoS) Flooding CDP table` کلیک می‌کنیم. بلافاصله در پنل پایین، جزئیات بسته CDP که قرار است ارسال شود را مشاهده می‌کنیم.
    
- **5: اجرای حمله:** بر روی دکمه `Launch` یا `Start` در نوار ابزار کلیک می‌کنیم. ارسال بسته‌های مخرب بلافاصله آغاز می‌شود و می‌توانیم تأثیر آن را بر روی دستگاه هدف بررسی کنیم.
    
- **6: توقف حمله:** برای پایان حمله، بر روی دکمه `Stop` کلیک می‌کنیم.

```sh
Password:
```
نام کاربری و رمز عبور پیش‌فرض را می‌توانیم در فایل پیکربندی (`/etc/yersinia/yersinia.conf`) تنظیم کنیم. پس از ورود موفق، با یک خط فرمان (CLI) شبیه‌سازی‌شده به سبک دستگاه‌های سیسکو مواجه می‌شویم.

---------------

2. **ب) دستورات داخلی CLI و اجرای حمله (پروتکل HSRP حمله Becoming Active Router):**  
در این محیط، می‌توانیم با دستورات متنی، پروتکل‌ها و حملات را مدیریت کنیم. برای نمونه، می‌خواهیم در پروتکل HSRP حمله Becoming Active Router (تصاحب روتر فعال) را از راه دور اجرا کنیم:

- **1: مشاهده وضعیت و پروتکل‌ها:** دستور `show protocols` لیست پروتکل‌های در دسترس را نشان می‌دهد.
```txt
yersinia> show protocols
```

- **2: فعال‌سازی پروتکل HSRP:** برای ورود به محیط پیکربندی پروتکل، دستور زیر را وارد می‌کنیم:
```txt
yersinia> enable hsrp
yersinia(hsrp)#
```

- **3: اجرای حمله:** از دستور attack به همراه شناسه عددی حمله برای اجرا استفاده می‌کنیم که برای حمله Becoming Active Router شماره 2 را باید وارد کنیم:
```txt
yersinia(hsrp)# attack 2
```
اکنون پیامی مبنی بر شروع حمله نمایش داده می‌شود. با `no attack 2` نیز می‌توانیم حمله را متوقف کنیم.

----------------

3. **ج) کاربرد و مزیت:** 
این روش یک مزیت بزرگ برای تیم‌های امنیت تهاجمی (Offensive Security Teams) دارد. می‌توانیم یک دستگاه کوچک (مثل Raspberry Pi) را به عنوان عامل Yersinia در شبکه هدف مستقر کرده و سپس تمامی حملات لایه 2 خود را از راه دور و بدون نیاز به لاگین مستقیم بر روی آن دستگاه، اجرا و مدیریت کنیم. این قابلیت، انعطاف‌پذیری فوق‌ العاده‌ای در تست نفوذ شبکه‌ های سگمنت‌شده ایجاد می‌کند.


##### Conclusion
در پایان این فصل و پس از بررسی عمیق ابزار Yersinia، به جمع‌بندی دستاوردها و اهمیت این ابزار قدرتمند در جعبه ابزار متخصصان امنیت شبکه می‌پردازیم.

ابزار Yersinia یک فریم‌ورک تخصصی، متن‌باز و انعطاف‌پذیر است که به طور خاص برای ارزیابی امنیت پروتکل‌های لایه دوم شبکه طراحی شده است. این ابزار با پشتیبانی از پروتکل‌های حیاتی زیرساخت شبکه مانند STP، VTP، HSRP، DTP، CDP، DHCP و غیره، به ما اجازه می‌دهد تا پیش از مهاجمان واقعی، آسیب‌پذیری‌های پنهان در پیکربندی سوییچ‌ها و روترها را کشف و تحلیل کنیم. آنچه Yersinia را از بسیاری از ابزارهای مشابه متمایز می‌کند، پشتیبانی از پروتکل هایی که در سایر ابزار ها مشاهده نمیشود، ارائه چندین واسط کاربری (GUI، Ncurses و Daemon) برای انطباق با سناریوهای مختلف و همچنین ارائه حملات پیشرفته‌ای است که برخی از آن‌ها برای اولین بار در این ابزار به صورت عمومی پیاده‌سازی شده‌اند.

**تأکید دوباره بر اصول اخلاقی:** تمامی دانش و مهارتی که در این فصل آموختیم، **صرفاً و منحصراً برای اهداف آموزشی، پژوهشی و تست نفوذ مجاز در محیط‌های آزمایشگاهی ایزوله و یا شبکه‌هایی که مجوز رسمی و کتبی برای ارزیابی آن‌ها دریافت شده است، کاربرد دارد**. استفاده از این تکنیک‌ها بر روی شبکه‌های در حال سرویس‌دهی بدون مجوز، غیرقانونی، غیراخلاقی و مصداق بارز سوءاستفاده است. مسئولیت هرگونه استفاده نادرست و عواقب ناشی از آن، کاملاً بر عهده استفاده‌کننده می‌باشد و هیچ‌گونه ارتباطی با نویسنده و ناشر این کتاب ندارد.

**فواید یادگیری و مسیر پیش رو:** یادگیری عمیق Yersinia تنها به معنای فراگیری یک ابزار نیست، بلکه دریچه‌ای به سوی درک بنیادین ضعف‌های ذاتی پروتکل‌های لایه دوم است که اغلب نادیده گرفته می‌شوند. با تسلط بر این مباحث:

1. **نگاه یک متخصص تهاجمی (Red Teamer):** ما قادر خواهیم بود حملات پیچیده مرد میانی (MITM) را در بستر VLAN ها، دستکاری ترافیک از طریق DHCP جعلی، و ایجاد اختلالات هدفمند از طریق حملات DoS مبتنی بر CDP یا STP را شبیه‌سازی کنیم.
    
2. **نگاه یک متخصص دفاعی (Blue Teamer):** ما توانایی شناسایی این حملات را از طریق تحلیل لاگ‌های سوییچ‌های Cisco (مشابه آنچه در خروجی‌های ابزار بررسی کردیم) به دست آورده و می‌آموزیم که چگونه با پیاده‌سازی دفاع‌های لایه 2 مانند BPDU Guard، Root Guard و DHCP Snooping، زیرساخت شبکه را در برابر این تهدیدات مقاوم‌سازی کنیم.
    
3. **مهارت نهایی:** ما اکنون به سطحی از درک رسیده‌ایم که می‌توانیم سناریوهای حمله را شخصی‌سازی کرده، خروجی‌ها را تحلیل کنیم و استراتژی‌های دفاعی متناسب با آن‌ها را طراحی نماییم. این دانش، گامی بلند در جهت تبدیل شدن به یک متخصص کامل در حوزه امنیت زیرساخت شبکه است.
